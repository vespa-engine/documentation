title: "Vespa インストールのセキュリティ確保"
---

<Note>
**Note:** 

このドキュメントは **Vespa をセルフホストしている場合**にのみ関係します。Vespa Cloud ではこれらは自動的に行われます。
</Note>

あらゆるネットワークシステムにおいて、セキュリティ要件と制限を理解することは極めて重要です。Vespa も例外ではありません。このドキュメントでは、ネットワークおよび物理ホストのレベルにおけるセキュリティに関して最も重要な情報を提供します。

セルフホストの Vespa インストールを安全に保つために、以下のガイドラインに従ってください:
1. Vespa のホストを隔離する
2. アクセス制御フィルターと TLS でアプリケーション・コンテナーを保護する
3. ディレクトリのパーミッションをロックダウンする
4. 相互認証 TLS（mTLS）で Vespa を保護する


## Vespa ホストの隔離

**セルフホストの Vespa インスタンスを実行する場合、Vespa を実行しているホストをパブリックインターネットや信頼できないネットワークに直接公開してはいけません。これを怠ると、データの持ち出し・侵入やホストの侵害につながる可能性があります。**

Vespa の内部プロトコルは、デフォルトでは認証されないため、信頼できないネットワーク上の主体に対して安全ではありません。自組織内で、特にパブリッククラウド上で Vespa を実行する場合、この点を考慮する必要があります。

Vespa のサービスを実行している*あらゆる*ホストへの接続は、管理された一連の信頼できるホストからの*みに*限定すべきです。すべての Vespa ホストは、同じインストールに属する他のすべての Vespa ホストに接続でき、また接続を受けられる必要があります。セキュリティをさらに高めるには、Vespa ホストが他の Vespa ホストとのみ通信できるように制限することを検討してください。アプリケーション・コンテナーで[フェデレーション](/ja/querying/federation)の一環として外部サービスに接続する場合は、コンテナーのホストがそれらのサービスに接続できる必要があります。

これは、例えば iptables、AWS Security Groups、または類似の技術で実装できます。

Vespa インストールへのエントリーポイントは、アプリケーション・コンテナーを実行しているホストのポート 8080 です。このポートは、フィード、ドキュメントの取得、検索クエリーに使用されます。[アプリケーション・コンテナーを適切に保護](#securing-the-application-container)している場合にのみ、信頼できないネットワークに公開すべきです。外部トラフィックに直接公開することは決してしないでください。コンテナーへのすべてのトラフィックは、お客様のフロントエンドまたはバックエンドから送信されるべきです。

Vespa インストール内のノード間通信は、デフォルトでは暗号化されておらず、[相互認証 TLS による Vespa の保護](/ja/security/mtls)に記載されているとおり、明示的に設定する必要があります。

## アプリケーション・コンテナーの保護

デフォルトでは、コンテナーは Vespa インストールに対する認証なしの書き込みと読み取りを許可します。プロダクションのデプロイメントでは、これをロックダウンする必要があります。

HTTP コンテナーへの接続は [TLS で保護](/ja/applications/http-servers-and-filters#tls)できます。相互 TLS がサポートされており、設定すべきです。

コンテナーの API エンドポイントへのアクセスは、[リクエストフィルター](/ja/applications/http-servers-and-filters#set-up-filter-chains)を使用して制御できます。これらのフィルターで、お客様の特定のユースケースに必要な認証および認可のロジックを実装できます。

制限的なフィルターロジックを伴う TLS を設定しない場合は、他の Vespa ホストと同じ方法でコンテナーのポートを制限すべきです。

## ディレクトリ・パーミッションのロックダウン

すべての Vespa プロセスは、`$VESPA_USER` で指定された Linux ユーザーとして実行され、データを `$VESPA_HOME` 以下に保存します。アプリケーションで機密データを保存する場合は、`$VESPA_HOME` 以下のファイルとディレクトリに他のユーザーがアクセスできないようにしてください。

また、コンテナーが TLS を設定するために使用する秘密鍵は、コンテナーのプロセスのみが読み取れるように保護する必要があることにも注意してください。

Vespa には、ディスク上のドキュメントストアやインデックスの暗号化に対するアプリケーションレベルのサポートはありません。これは通常、ファイルシステムまたはストレージレベル（例: リモートのクラウドストレージ）の暗号化によって実装されます。

## 相互認証 TLS（mTLS）による Vespa の保護

Vespa のすべての内部エンドポイントとプロトコルを、相互認証された Transport Layer Security（mTLS）で保護してください。始め方については[専用のドキュメント](/ja/security/mtls)を参照し、[multinode-HA](https://github.com/vespa-engine/sample-apps/tree/master/examples/operations/multinode-HA) の例を試してみてください。
