## 保存済み検索と複数通貨の組み合わせ

[保存済み検索通知](/ja/modules/e-commerce/saved-search)と[複数通貨の価格設定](/ja/modules/e-commerce/multi-currency-filtering)を組み合わせて使用する場合、保存済み検索のドキュメント・プロセッサーはフィード時に通貨ごとの価格フィーチャーを生成します。これにより、価格フィルターを持つ保存済み検索は、販売者の通貨に関係なく商品にマッチできます。

### 仕組み

複数通貨を使用しない場合、`price in [100..200]` のような保存済み検索は、商品の単一の `price` フィールドに対してマッチします。複数通貨を有効にすると、ドキュメント・プロセッサーは次の処理を行います:

1. 商品の `per_market_price` エントリと `seller_currency` を読み取ります
2. 為替レートを使用して、各価格を既知のすべての通貨に換算します
3. 換算した価格に `priceScaleFactor` を掛けて整数にスケーリングします(たとえば、係数 100 は小数点以下 2 桁を保持します)。predicate の範囲には整数値が必要なため、精度を保持するためにこのステップが必要です。
4. `{featurePrefix}_{currency}_{market}` という名前の predicate 範囲フィーチャー(例: `price_NOK_DEFAULT`、`price_EUR_NO`)を生成します
5. これらのフィーチャーを通常のアトリビュートとともに predicate クエリーにフィードします

これにより、NOK 価格でフィルターする保存済み検索は、predicate 式として `price_NOK_DEFAULT in [1000..1500]` を使用でき、元がどの通貨で価格設定された商品にもマッチします。

### predicate の上限値

保存済み検索スキーマ内の predicate フィールドの `upper-bound` は、スケーリング後の換算価格の最大値をカバーできる十分な大きさでなければなりません。価格は通貨換算され、さらに `priceScaleFactor` でスケーリングされるため、結果の値は元の価格よりも大幅に大きくなる可能性があります。

<Warning>
 **警告:** predicate クエリー内の 1 つでも範囲フィーチャーが `upper-bound` を超えると、Vespa は範囲外のフィーチャーだけでなく、そのドキュメントの predicate クエリー**全体**を拒否します。これは、その商品がどの保存済み検索にもまったくマッチしなくなることを意味します。
</Warning>

たとえば、スケール係数が 100 で、EUR から SEK へのレートが約 11.76 の場合: 200 EUR の商品は `price_SEK_DEFAULT = 200 Ã— 11.76 Ã— 100 = 235,294` を生成します。これが機能するためには、`upper-bound` は少なくとも 235,294 でなければなりません。

最も高価格の商品を最も弱いターゲット通貨に換算し、スケール係数を掛けた値をカバーする上限値を選択してください。価格や為替レートの変動に対応できるよう、余裕を持たせることを推奨します。

### スキーマの設定

以下は、各機能に必要なフィールドを示す最小限の例です。実際のスキーマには、追加のフィールドや設定が含まれることが多いでしょう。

#### 商品スキーマ

商品スキーマには、両方の機能のフィールドを含める必要があります。すなわち、保存済み検索のアトリビュート(`price`、`category` など)と、複数通貨のフィールド(`seller_currency`、`per_market_price`)です。

```js expandable
schema product {
    document product {

        # Saved search attributes
        field price type int {
            indexing: attribute
        }

        field category type string {
            indexing: attribute
        }

        # Multi-currency fields
        field seller_currency type string {
            indexing: summary | attribute
        }

        struct market_price {
            field market type string {}
            field price type double {}
        }

        field per_market_price type array<market_price> {
            indexing: summary
            summary: matched-elements-only
            struct-field market {
                indexing: attribute
            }
            struct-field price {
                indexing: attribute
            }
        }
    }
}
```

#### 保存済み検索スキーマ

スケーリング後の換算価格をカバーできる十分な高さに `upper-bound` を設定してください。上記の [predicate の上限値](#predicate-upper-bound)を参照してください。

```js expandable
schema saved_search {
    document saved_search {
        field filters type predicate {
            indexing: attribute
            index {
                arity: 2
                lower-bound: 3
                upper-bound: 250000

                dense-posting-list-threshold: 0.25
            }
        }
    }
}
```

### サービスの設定

両方の機能は同じコンテナー・クラスターで設定します。以下の例は組み合わせた設定を示しています - 重要な追加点は、ドキュメント・プロセッサーの `ecommerce-schema-wiring` 設定内の `multicurrency` ブロックです:

```xml expandable
<services version="1.0">
    <container id="default" version="1.0">
        <search>
            <chain id="multi-currency-filter" inherits="vespa">
                <searcher id="ai.vespa.ecommerce.multicurrency.MultiCurrencyFilterSearcher"
                          bundle="ecommerce-multi-currency" />
            </chain>
            <chain id="forex-cache" inherits="vespa" />
        </search>
        <document-api />

        <!-- Multi-currency components -->
        <component id="ai.vespa.ecommerce.common.ForexRateService"
                   class="ai.vespa.ecommerce.multicurrency.CachedForexRateService"
                   bundle="ecommerce-multi-currency" />
        <component id="ai.vespa.ecommerce.multicurrency.ForexRateRetriever"
                   bundle="ecommerce-multi-currency" />

        <!-- Saved search document processing -->
        <document-processing>
            <chain id="notification">
                <documentprocessor id="ai.vespa.ecommerce.savedsearch.SavedSearchDocumentProcessor"
                                   bundle="ecommerce-saved-search" />
                <config name="ai.vespa.ecommerce.common.ecommerce-schema-wiring">
                    <notification>
                        <kind>WEBHOOK</kind>
                        <webhook>
                            <URL>http://my-webhook-endpoint:8000/notification</URL>
                        </webhook>
                    </notification>

                    <productFields>
                        <sellerCurrency>seller_currency</sellerCurrency>
                        <perMarketPriceArrayStruct>per_market_price</perMarketPriceArrayStruct>
                        <marketStructField>market</marketStructField>
                        <priceStructField>price</priceStructField>
                    </productFields>

                    <productDocumentType>product</productDocumentType>
                    <savedSearchDocumentType>saved_search</savedSearchDocumentType>
                    <predicateFieldName>filters</predicateFieldName>

                    <regularAttributes>
                        <item>
                            <predicateName>category</predicateName>
                            <fieldPath>category</fieldPath>
                            <required>false</required>
                        </item>
                    </regularAttributes>
                    <rangeAttributes>
                        <item>
                            <predicateName>price</predicateName>
                            <fieldPath>price</fieldPath>
                            <required>false</required>
                        </item>
                    </rangeAttributes>

                    <!-- Enable multi-currency price features -->
                    <multicurrency>
                        <enabled>true</enabled>
                        <featurePrefix>price</featurePrefix>
                        <priceScaleFactor>100</priceScaleFactor>
                    </multicurrency>
                </config>
            </chain>
        </document-processing>
    </container>

    <content id="content" version="1.0">
        <documents>
            <document type="saved_search" mode="index" />
            <document type="product" mode="index" />
            <document type="forex" mode="index" global="true" />
        </documents>
    </content>

    <routing version="1.0">
        <routingtable protocol="document">
            <route name="notification-route" hops="forkhop" />
            <hop name="forkhop" selector="[DocumentRouteSelector]">
                <recipient session="default/chain.notification" />
                <recipient session="content" />
            </hop>
        </routingtable>
    </routing>
</services>
```

これらのパラメーターは `ecommerce-schema-wiring` 設定の一部であり、保存済み検索のドキュメント・プロセッサーを複数通貨と組み合わせて使用する場合にのみ適用されます:

</Info>

### フィードのワークフロー

両方の機能が有効な場合、フィードのワークフローは次のとおりです:

1. 為替ドキュメント(`id:forex:forex::forex`)をフィードし、`CachedForexRateService` が `READY` 状態になるのを待ちます
2. 保存済み検索ドキュメントをコンテント・クラスターにフィードします
3. 商品を `notification-route` にフィードします - ドキュメント・プロセッサーが複数通貨の predicate フィーチャーを生成し、保存済み検索とのマッチングを行います

<Warning>
 **警告:** 商品を notification route にフィードする前に、為替レートがロードされている必要があります。`ForexRateService` の準備ができていない場合、ドキュメント・プロセッサーは通貨換算された価格フィーチャーを生成できません。
</Warning>
