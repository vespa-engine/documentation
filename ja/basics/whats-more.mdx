その他の重要な機能には次のようなものがあります:

- **[グルーピングと集約](/ja/querying/grouping)**(ファセット): クエリー言語のグルーピングを使用すると、参加しているすべてのノードに分散されたクエリーへのすべてのマッチに対して実行される、階層的なグルーピングと集約を指定できます。
- **ストリーミング検索**: クエリーが全データのうち固定された小さなサブセット(ユーザーやテナントなど)のみを検索するアプリケーションでは、インデックスを構築することはコスト効率が良くありません。このようなユース・ケース向けに、Vespa は[ストリーミング・モード](/ja/performance/streaming-search)をサポートしており、インデックスの維持やデータをメモリーに保持するコストなしに、低レイテンシーの検索を提供します。
- **アプリケーション・コンポーネント**: アプリケーションには、アプリケーション・ロジックを実装する Java コンポーネントを含めることができます。たとえば、クエリーと結果をインターセプトしてカスタム・ワークフローを実装する([サーチャー](/ja/applications/searchers))、書き込み操作を変更する([ドキュメント・プロセッサー](/ja/applications/document-processors))、カスタム API を実装する([ハンドラー](/ja/applications/request-handlers))などです。
- **親子関係**: Vespa では、スケールしないため結合(join)はサポートされていませんが、結合の片側がもう一方より大幅に小さいという特殊なケースはサポートされています。これは[親子関係](/ja/schemas/parent-child)と呼ばれます。
- **フェデレーション**: 多くのアプリケーションは、複数の種類のコンテンツにまたがってフェデレーションを行います。Vespa はデフォルトですべてのスキーマとクラスターにまたがってフェデレーションを行い、[フェデレーション・フレームワーク](/ja/querying/federation)を備えています。これにより、各コンテンツ・タイプへのクエリーを組み立てるアプリケーション固有のスキームを定義したり、他のサービスからコンテンツを取り込んだり、アプリケーション固有の方法でコンテンツを組み合わせたりできます。
- **述語フィールド**: クエリーとともに送信されるプロパティに対する条件として、ドキュメントがいつマッチすべきかをドキュメント側で指定できると便利な場合があります。たとえば、コンテンツを特定の種類のユーザーに向けてターゲティングする場合です。これは[述語フィールド](/ja/schemas/predicate-fields)を使用して実現できます。
- **ジオ検索**: [ジオ・フィールド](/ja/querying/geo-search)を使用すると、指定されたエリア内のドキュメントを検索したり、クエリーとの距離をランキングに使用したり、ルート計画のために経路との距離で取得したりすることもできます。
- **ミュータブル属性**: ドキュメントに[ミュータブル属性](/ja/reference/schemas/schemas#mutate)を定義することで、アプリケーションは各ドキュメントの統計をリアルタイムに収集し、それらがどのくらいの頻度でマッチし、ランキングされ、結果として返されたかを追跡できます。

詳細は完全な[機能](/ja/learn/features)一覧を参照してください。
