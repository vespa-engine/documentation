## vespa-analyze-onnx-model

ONNX モデルをロードして、メモリ使用量を分析し、入力タイプに基づいて出力タイプを推論/プローブします。

構文: `vespa-analyze-onnx-model <onnx-model> [options...]`

例(その他の例は [ONNX](/ja/ranking/onnx) を参照):

```bash
$ vespa-analyze-onnx-model Network.onnx
```

  <thead>
    <tr>
      <th>オプション</th>
      <th>説明</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><strong>--probe-types</strong></td>
      <td>onnx モデルを使用して、入力タイプに基づいて出力タイプを推論/プローブします</td>
    </tr>
  </tbody>
</table>

## vespa-fbench

*vespa-fbench* は、Vespa システムの容量のベンチマークに使用します。使用方法と例については、[vespa-benchmarking](/ja/performance/benchmarking) を参照してください。

複数のホスト名とポートを使用して、負荷をラウンドロビンでクライアントに分散させることができます。

構文: `vespa-fbench [options] <hostname> <port>`

例:

```bash
$ vespa-fbench -n 10 -q query%03d.txt -s 300 -c 0 -o output%03d.txt -xy test.domain.com 8080
```

## vespa-makefsa

*vespa-makefsa* は、フレーズのリストを *有限状態オートマトン*(FSA)ファイルにコンパイルするために使用します。FSA ファイルは、[クエリーのフレーズ化と書き換え](/ja/linguistics/query-rewriting)で使用されます。

入力ファイルが指定されていない場合は、標準入力が使用されます。

構文: `vespa-makefsa [-h] [-b] [-B] [-e] [-n] [-s bytes] [-z bytes] [-t] [-p] [-i] [-S serial] [-v] [-V] [input_file] output_file`

## vespa-query-profile-dump-tool

一連のディメンション値に対して、解決済みのすべてのクエリープロファイルプロパティをダンプします

構文:`vespa-query-profile-dump-tool dump [query-profile] [dir]? [parameters]?`

例:

```bash
dump default                           # dumps the 'default' profile non-variant values in the current dir

dump default x=x1&y=y1                 # dumps the 'default' profile resolved with dimensions values x=x1 and y=y1 in the current dir

dump default myapppackage              # dumps the 'default' profile non-variant values in myapppackage/search/query-profiles

dump default dev/myprofiles x=x1&y=y1  # dumps the 'default' profile resolved with dimensions values x=x1 and y=y1 in dev/myprofiles
```
