このリファレンスでは、Vespa の _インデックス言語_ の全体をドキュメント化します。入力データに対してより複雑な処理が必要な場合は、[ドキュメントプロセッサー](/ja/applications/document-processors)を実装してください。

インデックス言語は UNIX のパイプに似ており、ステートメントは _パイプ_ 記号で区切られた式で構成され、各式の出力が次の式の入力になります。ステートメントはセミコロンで終端され、(変数を使用する場合を除いて)互いに独立しています。

例は[インデックス](/ja/writing/indexing)ガイドを参照してください。

## インデックススクリプト

インデックススクリプトは、セミコロン(`;`)で区切られた一連の[インデックスステートメント](#indexing-statement)です。スクリプトは、一度に 1 つのドキュメントに対して、ステートメントごとに順番に実行されます。

Vespa は、各検索クラスターに割り当てられた検索定義に基づいて、検索クラスターごとに 1 つのインデックススクリプトを導出します。ドキュメントが検索クラスターにフィードされると、対応する[インデックスクラスター](/ja/reference/applications/services/content#document-processing)を通過し、そこでドキュメントに対してインデックススクリプトが実行されます。これはドキュメントが[再インデックス](/ja/operations/reindexing)されるたびにも行われるため、[now](#now) などの式は、ドキュメントが _フィード_ された時刻ではなく、(最後に)_インデックス_ された時刻と考える必要があることに注意してください。

特定の検索クラスター用に生成されたインデックススクリプトは、インデックスドキュメントプロセッサーの構成を取得することで確認できます。

```sh
$ vespa-get-config -i search/cluster.<cluster-name> -n vespa.configdefinition.ilscripts
```

現在の _実行値_ は、ステートメントの実行前に `null` に設定されます。

## インデックスステートメント

インデックスステートメントは、パイプ(`|`)で区切られた一連の[インデックス式](#indexing-expression)です。ステートメントは、式ごとに順番に実行されます。

ステートメント内では、実行値がある式から次の式へと渡されます。

最も単純なステートメントは、入力フィールドの値をアトリビュートに渡すものです:

```sh
input year | attribute year;
```

上記のステートメントは、`input year` と `attribute year` という 2 つの式で構成されます。前者は、実行値を入力ドキュメントの「year」フィールドの値に設定します。後者は、現在の実行値をアトリビュート「year」に書き込みます。

## インデックス式

### プリミティブ

文字列、数値リテラル、および true/false は、実行値を明示的に設定するための式として使用できます。例: `"foo"`、`69`、`true`)。

### 出力

出力式は、現在の実行値をドキュメントのフィールドに書き込む式です。これらの式は、構築するフィールドの種類(すなわち attribute、index、または summary)を示すインジケーターとしての役割も兼ねます。1 つのドキュメント内で同じフィールドに異なる値を割り当てることはできない点に注意してください(例えば `attribute | lowercase |
index` は **不正** であり、デプロイできません)。

### 算術演算

インデックスステートメントには、オペランドが数値である限り、算術演算を自由に組み合わせて含めることができます。文字列から数値への変換や、ある数値型から別の数値型への変換が必要な場合は、該当する[コンバーター](#converters)式を使用してください。サポートされている算術演算子は次のとおりです:

    </tr>
    <tr>
      <td><code>{`<lhs> * <rhs>`}</code></td>
      <td>実行値を、<code>{`lhs`}</code> 式の実行値に <code>{`rhs`}</code> 式の実行値を乗算した結果に設定します。</td>
    </tr>
    <tr>

    <tr>

      <td>実行値を、<code>{`lhs`}</code> 式の実行値を <code>{`rhs`}</code> 式の実行値で除算した余りに設定します。</td>
    </tr>
    <tr>
      <td><code>{`<lhs> . <rhs>`}</code></td>
      <td>実行値を、<code>{`lhs`}</code> 式の実行値と <code>{`rhs`}</code> 式の実行値を連結したものに設定します。<code>{`lhs`}</code> と <code>{`rhs`}</code> の _両方_ がコレクション型の場合、この演算子は <code>{`rhs`}</code> を <code>{`lhs`}</code> に追加します(いずれかのオペランドが null の場合、空のコレクションとして扱われます)。そうでない場合、この演算子は <code>{`lhs`}</code> と <code>{`rhs`}</code> の文字列表現を連結します(いずれかのオペランドが null の場合、結果は null になります)。</td>
    </tr>
  </tbody>
</table>

実行の優先順位を宣言するために括弧を使用できます(例: `(1
  + 2) * 3`)。これは、`(input str_a | split ',') . (input str_b | split
  ',') | index arr` のような、より高度な配列連結ステートメントでも機能します。
