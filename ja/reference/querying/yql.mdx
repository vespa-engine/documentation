Vespa は、非構造化の人間による入力と、アプリケーションロジックのための構造化クエリーを別々に受け取り、それらを実行のための単一のデータ構造に結合します。人間による入力はヒューリスティックに解析され、アプリケーションのクエリーは YQL で記述されます。

<Info>
 **注:** クエリーの例については[クエリー言語ガイド](/ja/querying/query-language)を参照してください
</Info>

クエリー URL は次のようになります:

```bash
http://myhost.mydomain.com:8080/search/?yql=select%20%2A%20from%20sources%20%2A%20where%20text%20contains%20%22blues%22
```

言い換えると、`yql` には次の内容が含まれます:

```bash
select * from sources * where text contains "blues"
```

これは、_text_ という名前のフィールドに _blues_ という単語が含まれるすべてのドキュメントに[マッチ](/ja/reference/schemas/schemas#match)します。

テキスト値内の引用符 `"` およびバックスラッシュ `\` 文字は、バックスラッシュでエスケープしなければなりません。[バックスラッシュによるエスケープの仕組み](/ja/learn/faq#how-does-backslash-escapes-work)も参照してください。

<Danger>
 **重要:** 設定されていない、または `null` や `NaN` に等しいフィールドをクエリーする方法はありません。ドキュメント内で通常使用されない「マジック」値(MAXINT など)を使用して回避してください。
</Danger>

## select

_select_ は、リクエストする[サマリーフィールド](/ja/querying/document-summaries#selecting-summary-fields-in-yql)(`summary` インデックス属性を持つフィールド)のリストです。Vespa は、マッチしたドキュメント内の他のフィールドを非表示にします。

```bash
select price,isbn from sources * where title contains "madonna"
```

上記は、(すべてのソースから)フィールド「price」と「isbn」を明示的にリクエストします。すべてのフィールドをリクエストするには、フィールド選択にアスタリスクを使用します:

```sql
select * from sources * where title contains "madonna"
```

## from sources

_from sources_ は、クエリー対象のコンテント・[ソース](/ja/reference/api/query#model.sources)を指定します。例:

```sql
select * from music where title contains "madonna"
```

は、_music_ コンテント・クラスターまたはフェデレーションソース内のすべてのドキュメントタイプをクエリーします。クエリー対象:

## order by

`order by` を使用してソートします。[attribute](/ja/content/attributes) の名前の後に `asc` または `desc` を追加してソート順を設定します。デフォルトは昇順です。別のソート attribute を追加すると二次ソートが得られ、これは一次ソート attribute のタイブレーカーとなります。これは通常、一次ソート attribute が複数のドキュメントで同じ値を持つ場合に、予測可能な順序を得るために使用されます。

where title contains "madonna" order by price asc, releasedate desc

ソート関数、ロケール、強度は、次のようにアノテーション「function」、「locale」、「strength」を使用して定義します:

```bash
where title contains "madonna" order by {function: "uca", locale: "en\_US", strength: "IDENTICAL"}other desc, {function: "lowercase"}something
```

<Info>
**注:** ソート時には [match-phase](/ja/reference/schemas/schemas#match-phase) が有効になります。[ソートのリファレンス](/ja/reference/querying/sorting-language)を参照してください。
</Info>
[ランクプロファイル](/ja/basics/ranking)は、各ドキュメントが得るランクスコアを決定します。結果はデフォルトでその値によって順序付けられますが、`order by` はその順序を上書きします。この場合でも Vespa はランクスコアの計算を最適化によって省略せず、モデルのスコアが破棄されるとしても計算は実行されます。ソートクエリーのパフォーマンスを最適にするには、組み込みの rank-profile *unranked* を使用してください。

ランクスコアで一次ソートを行い、attribute で二次ソートを行うには、最初の order by の attribute として `'[relevance]'` を使用します。詳細は[特殊なソート attribute](/ja/reference/querying/sorting-language#special-sorting-attributes)を参照してください。

## limit / offset

スライスの指定、返されるヒット数の制限、ページネーションを行うには、`limit` や `offset` を使用します。これは[ネイティブ実行パラメーター](/ja/reference/api/query#native-execution-parameters)を使用して制御することもできます。

<Danger>
**重要:** YQL で設定された値は [hits/offset](/ja/reference/api/query#hits) より優先されます。クエリープロファイル内の hits/offset の値も YQL によって上書きされます。例えば、`limit 100` は `<field name="hits" overridable="false">50</field>` を上書きします。
</Danger>

[maxHits](/ja/reference/api/query#hits)(デフォルト 400)と [maxOffset](/ja/reference/api/query#offset)(デフォルト 1000)によって制限されます。これらは [queryProfile](/ja/querying/query-profiles) で設定できます。

例: これは、最初の 29 件のドキュメントをスキップして、(クエリーにマッチするヒットが十分にある場合)2 件のヒットを返します

<Card>
where title contains "madonna" limit 31 offset 29
</Card>
## timeout

`timeout` を使用して、クエリーのタイムアウトをミリ秒単位で設定します。これはネイティブ実行パラメーター [timeout](/ja/reference/api/query#timeout) を使用して制御することもできます。YQL で指定された値が優先されます。:

<Card>
where title contains "madonna" timeout 70
</Card>
リテラルの数値のみが有効です。つまり、別の単位を設定することはサポートされていません。

<Note>
**注:** この値はミリ秒単位ですが、ネイティブ実行パラメーター [timeout](/ja/reference/api/query#timeout) は秒単位です
</Note>
## パラメーター置換

パラメーター置換を使用して、YQL 文字列をユーザー入力値から分離します。例えば、[text(value)](#text) クエリー演算子は、`value` パラメーターのパラメーター置換をサポートしています:

<Card>
... where default contains text(@userinput)&userinput=free+text
</Card>

クエリー演算子 [field in (value)](#in)、[dotProduct(field, value)](#dotproduct)、[weightedSet(field, value)](#weightedset)、[wand(field, value)](#wand) は、`value` パラメーターのパラメーター置換をサポートしています。

`value` 文字列は、次のいずれかの形式で渡すことができます(キーに `,` または `:` が含まれない限り、クォートは省略できます):

- リスト: `value, ...`。[in](#in) 演算子専用。
- 配列: `[[key, value], ...]`。[dotproduct](#dotproduct)、[weightedset](#weightedset)、[wand](#wand) 用。
- マップ: `{key: value, ...}`。[dotproduct](#dotproduct)、[weightedset](#weightedset)、[wand](#wand) 用。

例については[クエリー API ガイド](/ja/querying/query-api#parameter-substitution)を参照してください。

## アノテーション

語やフレーズにアノテーションを付けて、挙動を操作できます。`{}` を使用してアノテーションを追加します:

```
where text contains ({distance: 5}near("a", "b")) and text contains ({distance:2}near("c", "d"))
```

アノテーションを演算子にスコープするために、アノテーションが括弧で囲まれていることに注意してください。

すべてのアノテーションは、phrase() や near() のような関数への文字列引数、および「contains」演算子への文字列引数でサポートされています。一部のアノテーションは、クエリーツリー内部で葉ノードのように扱われる関数でもサポートされています: phrase()、near()、onear()、range()、equiv()、dotProduct()、weightedSet()、weakAnd()、wand()、nearestNeighbor()。

使用例については [SelectTestCase.java](https://github.com/vespa-engine/vespa/blob/master/container-search/src/test/java/com/yahoo/select/SelectTestCase.java) を参照してください。

### 部分式のアノテーション

次のクエリーを考えます:

```sql
select * from sources * where ({stem: false}(foo contains "a" and bar contains "b")) or foo contains ({stem: false}"c")
```

「stem」アノテーションは、フィールドがステミング対象フィールドとして設定されている場合に、その語をステミングすべきかどうかを制御します(デフォルトは「true」)。「AND」演算子自体には、そのオペランドをステミングすべきかどうかについての内部 API はありませんが、それでもこのようにアノテーションを付けることができます。これは、あるアノテーションの値が決定される際に、対象の語からその祖先へと式ツリーがたどられるためです。ツリーの走査は、値が見つかった時点で(または走査するものがなくなった時点で)停止します。言い換えると、この例のどの語もステミングされません。

アノテーションの挙動は、ブールクエリーを S 式のスタイルで表現すると理解しやすいかもしれません:

```sql
(AND term1 term2 (OR term3 term4) (OR term5 (AND term6 term7)))
```

この場合、アノテーションのスコープは次のようになります。すなわち、ある語の設定を決定する際に、どの要素のアノテーションがチェックされるかを示します:

## クエリープロパティ

YQL の変数構文を使用して、フレーズ内の単語や単独の語を初期化します。これにより、YQL 内での語のクォートや URL クォートを気にする必要がなくなります。語は URL にあるものと_まったく同じように_使用されます。例として、YQL 引数と、プロパティ _animal_ および _syntaxExample_ を持つクエリーを見てみましょう:

```bash
yql=select * from sources * where foo contains @animal and foo contains phrase(@animal, @syntaxExample, @animal)&animal=panda&syntaxExample=syntactic
```

この YQL 式はクエリープロパティ _animal_ と _syntaxExample_ にアクセスし、次のように評価されます:

```sql
select * from sources * where (foo contains "panda" AND foo contains phrase("panda", "syntactic", "panda"))
```

## クエリープロファイル内の YQL

YQL を URL に含めるにはクォートが必要です。YQL はエンドユーザー向けではなくアプリケーションロジックに適しているため、この問題の解決策の 1 つは、アプリケーションの YQL クエリーを個別の[クエリープロファイル](/ja/querying/query-profiles)に格納することです。デフォルトのクエリープロファイルを追加するには、[アプリケーション・パッケージ](/ja/reference/applications/application-packages)に _search/query-profiles/default.xml_ を追加します:

```xml
<query-profile id="default">
    <field name="yql">select * from sources * where default contains "latest" or userQuery()</field>
</query-profile>
```

これは、明示的なクエリープロファイル・パラメーターを持たないすべてのクエリーに、_latest_ を _OR 語_として追加します。注目すべき重要な点は、クエリープロファイルのファイル内では何も URL クォートする必要がないことです。これらは HTTP の解析そのものとは独立して動作します。

## Searcher でのクエリー書き換え

テキストの YQL 文を変更する Searcher(非推奨)には、`@Before("ExternalYql")` のアノテーションを付けるべきです。入力の YQL 文から生成されたクエリーツリーを変更する Searcher には、`@After("ExternalYql")` のアノテーションを付けるべきです。

## グルーピング

`|` の後にグルーピング式を追加して、結果をグループ化/集約します。[詳細を読む](/ja/querying/grouping)。

```sql
select * from sources * where sddocname contains 'purchase' | all(group(customer) each(output(sum(price))))
```
