グルーピングの例と入門については、まず[Vespaグルーピングガイド](/ja/querying/grouping)をお読みください。本ページはVespaグルーピングのリファレンスです。

また、グルーピング式で[マルチバリュー](/ja/querying/searching-multivalue-fields)・アトリビュート(doubleの配列など)を使用するとパフォーマンスに影響することにも注意してください。このような操作は、より多くのデータが評価されるため、特に処理対象のヒット集合が大きい場合に、メモリー帯域幅のボトルネックに達する可能性があります。

## グループ

カスタム式を使用してクエリー結果をグループ化します(`group`句を使用):

- 数値または文字列の定数(例:`group(1)`や`group("all")`)。これはすべてを含む1つのバケットを作成します
- ドキュメントの[アトリビュート](/ja/content/attributes)
- 別の式に対する関数(`xorbit`、`md5`、`cat`、`xor`、`and`、`or`、`add`、`sub`、`mul`、`div`、`mod`)、またはその他の任意の[式](#expressions)
- 式のデータ型は、一般的なプログラミング言語が異なるデータ型のオペランド同士の算術を解決するのと同様に、ベストエフォートで解決されます
- 任意の式の結果は、スカラーまたは1次元配列のいずれかです
  - `add(<array>)`は、すべての要素を加算してスカラーを生成します
  - `add(<arrayA>, <arrayB>)`は、各要素同士を加算し、サイズが`max(|<arrayA>|, |<arrayB>|)`の新しい配列を生成します

グループは(`each`および`group`操作を使用して)サブグループを含むことができ、任意のレベルまでネストできます。

複数の並列な`each`句または`all`句を使用して、同じグループレベルの下に複数のサブグルーピングや出力を作成でき、それぞれに[as(mylabel)](#labels)を使用してラベルを付けることができます。

結果をグループ化すると、_出力(outputs)_、_グループリスト(group lists)_、_ヒットリスト(hit lists)_ を含む _グループ(groups)_ が生成されます。グループリストにはサブグループが含まれ、ヒットリストには所属するグループの一部であるヒットが含まれます。

グループの識別情報は、その _id_ によって保持されます。long、double、stringなどのスカラーの識別情報は _id_ から直接取得できますが、バケット集約に使用される範囲の識別情報は、サブノードの _from_ と _to_ に分離されます。[結果フォーマットのリファレンス](/ja/reference/querying/default-result-format)を参照してください。

### マルチバリュー・アトリビュート

[マルチバリュー](/ja/querying/searching-multivalue-fields)・アトリビュートとは、[weighted set](/ja/reference/schemas/schemas#weightedset)、[配列](/ja/reference/schemas/schemas#array)、または[マップ](/ja/reference/schemas/schemas#map)のことです。ほとんどのグルーピング関数は、マルチバリュー・アトリビュートの要素を、あたかもそれぞれが別々のドキュメント内の個別の値であるかのように、単純に個別に処理します。構造体の配列やマップに対してグループ化する場合は、構造を保持するためにスコーピングが使用されます。配列/マップの各エントリーは、個別のサブドキュメントとして扱われます。_マップ_ アトリビュート・フィールドでグループ化する場合、次の構文を使用できます。

マップのキーでグループ化:

```bash
all( group(mymap.key) each(output(count())) )
```

マップのキーでグループ化し、その後マップの値でグループ化:

```bash
all( group(mymap.key) each( group(mymap.value) each(output(count())) ))
```

キー _my\_key_ の値でグループ化:

```bash
all( group(my_map{"my_key"}) each(output(count())) )
```

マップ要素 _my\_key_ で参照される構造体フィールド _my\_field_ でグループ化:

```bash
all( group(my_map{"my_key"}.my_field) each(output(count())) )
```

キーは(上記のように)直接指定することも、キー・ソース・アトリビュートを介して間接的に指定することもできます。キーは、ドキュメントごとにキー・ソース・アトリビュートから取得されます。キー・ソース・アトリビュートは単一値であり、マップのキー型と同じデータ型である必要があることに注意してください:

```bash
all( group(my_map{attribute(my_key_source)}) each(output(count())) )
```

整数の配列フィールドでグループ化:

```bash
all( group(my_array) each(output(count())) )
```

構造体の配列 _my\_array_ 内の構造体フィールド _my\_field_ でグループ化:

```bash
all( group(my_array.my_field) each(output(count())) )
```

[テンソル](/ja/reference/schemas/schemas#tensor)はグルーピングでは使用できません。

## グループのフィルタリング

マルチバリュー・アトリビュートでグループ化する場合、特定の値のみが収集されるようにグループをフィルタリングすると便利なことがあります。これは、フィルターを追加することで実現できます。`filter`句は、フィルター _述語(predicate)_ を取ります:

- [regex("regular expression", input-expression)](#regex-filter)
- [range(min-limit, max-limit, input-expression)](#range-filter)
- [range(min-limit, max-limit, input-expression, bool, bool)](#range-filter)
- [istrue(input-expression)](#istrue-filter)
- [not _述語_](#logical-predicates-filter)
- [_述語_ and _述語_](#logical-predicates-filter)
- [_述語_ or _述語_](#logical-predicates-filter)

### Regexフィルター

正規表現を使用して入力をマッチさせ、マッチしたドキュメントのみをグルーピングに含めます。入力は通常、「group」句と同じ式になります。例:

```bash
all( group(my_array) filter(regex("foo.*", my_array)) ...)
```

ここでは、_my\_array_ 内の「foo」プレフィックスで始まる値のみがグループに収集され、それ以外はすべて無視されます。[こちらの例](/ja/querying/grouping#structured-grouping)も参照してください。

Regexフィルタリングは、任意のフィールド型の文字列表現に対して機能します。たとえば、regex(true)とregex(false)を使用してブール値でフィルタリングすることもできます。

### Rangeフィルター

フィールド値が下限と上限の間にあるドキュメントをマッチさせるには、`range`フィルターを使用します。例:

```bash
all( group(some_field) filter(range(1990, 2012, year)) ...)
```
ここでは、下限は境界値を _含み_(year ≥ 1990)、上限は境界値を _含みません_(year \< 2012)。末尾のオプションのbool値を使用して、下限と上限をそれぞれ含めるかどうかを制御します。最初のboolは下限を境界値込みに設定し、2番目のboolは上限を境界値込みに設定します。
```bash
all( group(some_field) filter(range(1990, 2012, year, true, true)) ...)
```
ここでは、下限と上限の両方が境界値を含みます。
### IsTrueフィルター

ブール式を使用してフィルタリングするには、`istrue`を使用します。式は、ブール・アトリビュートなど、ブール値に評価されるものでなければなりません。例:

```bash
all( group(some_field) filter(istrue(my_bool_attribute)) ...)
```
ここでは、_my\_bool\_attribute_ がtrueに評価されるドキュメントのみがグルーピングに含まれます。
### 論理述語

別のフィルター式を否定するには、`not`を使用します。これは単一のサブフィルターを取り、そのサブフィルターがマッチしない場合にマッチします。例:

```bash
all( group(my_field) filter( not regex("bar.*", my_other_field)) ...)
```
2つのサブフィルターの論理和を取るには、`or`を使用します。結合されたフィルターは、いずれかのサブフィルターがtrueに評価される場合にマッチします。例:
```bash
all( group(my_field) filter( regex("bar.*", my_field) or regex("baz.*", my_third_field) ) ...)
```
2つのサブフィルターの論理積を取るには、`and`を使用します。結合されたフィルターは、すべてのサブフィルターがtrueに評価される場合にのみマッチします。例:
```bash
all( group(my_field) filter( regex("bar.*", my_other_field) and regex("baz.*", my_third_field) ) ...)
```
これらの論理述語をネストして、複雑なフィルター条件を作成できます。フィルター式は _一般的な優先順位_ の規則に従います:`not`は`and`より先に評価され、`and`は`or`より先に評価されます。同じ優先順位の演算子は、左から右へ評価されます。必要に応じて、括弧`(...)`を使用して異なるグループ化を強制します。例:
```bash
all(
    group(my_field)
    filter( (regex("bar.*", some_field) or regex("baz.*", other_field)) and not regex(".*foo", some_field))
    each(...)
)
```

## Order / max

グルーピングの各レベルでは、そのグループの順序付け方法を指定できます(`order`を使用):

- 順序付けには、使用可能な任意の集約関数を使用できます
- マルチレベルのグルーピングにより、プライマリーの集約値が等しい場合でも厳密な順序付けが可能です
- 順序付けは昇順または降順のいずれかで、順序付けのレベルごとに指定します
- グループは[ロケールを考慮したソート](#uca)を使用してソートされます

`max`を使用して各レベルで返されるグループ数を制限し、`order`で指定された順序の最初の _n_ 個のグループのみを返します:

- `order`は、次の集約関数についてはマージ操作後のグループの順序を変更します:`count`、`avg`、` sum`
- `order`は、`max`または`min`が使用されている場合、マージ操作後のグループの順序を**変更しません**
- デフォルトの順序である`-max(relevance())`は、[precision](#precision)の使用を**必要としません**

## Continuations

グルーピング結果のページネーションは、`continuations`によって管理されます。これらは不透明(opaque)なオブジェクトであり、組み合わせて、クエリーのグルーピング・ステップの`continuations`アノテーションとして再送信することで、結果リストの前のページや次のページに移動できます。

すべてのルート・グループには、`select`ごとに1つの _this_ continuationが含まれます。このcontinuationは現在のビューを表し、唯一のcontinuationとして送信された場合、それを含んでいた結果とまったく同じ結果を再現します。

グループリストおよびヒットリストごとに、0個または1個の _prev_/_next_ continuationがあります。これらを任意の数だけ送信して、対応するリストの次/前のページを取得できます

1つのクエリーで任意の数のcontinuationを組み合わせることができますが、最初のものは常に _this_ continuationでなければなりません。たとえば、あるリストの次のページと、別のリストの前のページに同時に移動することもできます。

<Info>
 **注:** 同じグループリストまたはヒットリストに対して複数のcontinuationオブジェクトが指定された場合、最後に指定されたものが有効になります。これは、continuationが指定された順に処理され、衝突するcontinuationを置き換えるためです。
</Info>

プログラムからグルーピングを扱う場合は、[RootGroup](https://javadoc.io/doc/com.yahoo.vespa/container-search/latest/com/yahoo/search/grouping/result/RootGroup.html)、[GroupList](https://javadoc.io/doc/com.yahoo.vespa/container-search/latest/com/yahoo/search/grouping/result/GroupList.html)、[HitList](https://javadoc.io/doc/com.yahoo.vespa/container-search/latest/com/yahoo/search/grouping/result/HitList.html)の各結果オブジェクト内にある[Continuation](https://javadoc.io/doc/com.yahoo.vespa/container-search/latest/com/yahoo/search/grouping/Continuation.html)オブジェクトを見つけてください。これらを[GroupingRequest](https://javadoc.io/doc/com.yahoo.vespa/container-search/latest/com/yahoo/search/grouping/GroupingRequest.html)のcontinuationリストに追加し直すことで、ページネーションを行うことができます。

例については[グルーピングガイド](/ja/querying/grouping#pagination)を参照してください。

## ラベル

`each`キーワードを使用して作成されたリストには、`each(...) as(mylabel)`という構文でラベルを割り当てることができます。each句によって作成される出力は、このラベルで識別されます。

```bash
all(group(year) each(output(count())) as(by_year))
```

個々の出力集約関数にも、`output(...)`内の集約関数に`as(mylabel)`を追加することでラベルを割り当てることができます。これは、グループリストではなく、集約結果にラベルを付けます。

```bash
all(group(author) output(count() as(authors_cardinality)))
```

## エイリアス

グルーピング式には _エイリアス_ のタグを付けることができます。エイリアスを使用すると、式をそのまま繰り返すことなく再利用できます。

```bash
all(group(a) alias(myalias, count()) each(output($myalias)))
```
 は、次と等価です
```bash
all(group(a) each(output(count())))
```
。
```bash
all(group(a) order($myalias=count()) each(output($myalias)))
```
 は、次と等価です
```bash
all(group(a) order(count()) each(output(count())))
```
。
## Precision

式の評価中に各コンテント・ノードから返される中間グループの数です。これにより、さらに評価するグループを選択する際に、コンテナー・ノードが考慮できるデータが増えます:`each(...) precision(1000)` 数値を大きくすると帯域幅のコストが増えますが、場合によっては精度が向上します。

## グルーピング・セッション・キャッシュ

<Danger>
 **重要:** グルーピング・セッション・キャッシュは、グルーピング式がデフォルトの順序付けを使用している場合に**のみ有用**です。**欠点**は、グルーピング式で`max`が指定されている場合、`count`などの集約値に不正確さが生じる可能性があることです。これが問題になるかどうかをテストし、問題になる場合は`precision`パラメーターを調整して正しいカウントが得られるようにすることを推奨します。
</Danger>

セッション・キャッシュは、マルチレベルのグルーピング式を使用する際に、中間のグルーピング結果をコンテント・ノードに保存します。これにより、精度が低下する可能性はあるものの、グルーピングを高速化できます。これによって、クエリーとグルーピング式は1回だけ実行されるようになります。

マルチレベルのグルーピング式がある場合、検索クエリーは通常、レベルごとに再実行されます。この方式の欠点は、コストの高いランキング関数を使用すると、クエリーに本来必要な時間よりも長い時間がかかることです。

## 集約関数

グルーピングの各レベルでは、そのグループに属するすべてのドキュメントに対して収集する集約のセットを指定します(`output`操作を使用):

- グループ内のドキュメント(指定されたサマリー・クラスを使用して取得)
- グループ内のドキュメント数
- 式のsum、average、min、max、xor、または標準偏差
- 式の値の複数の分位数(quantile)

すべての引数が数値の場合、結果の型は引数の型を見て解決されます。すべての引数がlongであれば、結果はlongになります。少なくとも1つの引数がdoubleであれば、結果はdoubleになります。

`order`を使用する場合、グループのソートをより細かく制御するために、集約関数を式の中で使用することもできます。ただし、アトリビュートを引数に取る式では、その式が集約関数で囲まれていない限り機能しません。

マルチバリュー・アトリビュートに対するsum、maxの使用について:`output(sum(myarray))`のような操作を行うと、各ドキュメント内の各要素値に対してsumが実行されます。結果は、値の合計の合計になります。同様に、`max(myarray)`は、すべてのドキュメントのすべての要素の中の最大要素を返します。以下同様です。

分位数を計算するには、目的の分位数の値を(カンマ区切りで)角括弧内に列挙し、その後にカンマと式(フィールドなど)を続けます:

```bash
all( group(city) each(output(quantiles([0.5], delivery_days) as(median_delivery_days) ) ) )
```
これは中央値を計算します。または
```bash
all( group(city) each(output(quantiles([0.5, 0.9], delivery_days))) )
```
これは、都市ごとの配達日数の中央値(p50)と90パーセンタイル(p90)を計算します。分位数は[KLL Sketch](https://datasketches.apache.org/docs/KLL/KLLSketch.html)を使用して計算されるため、近似値であることに注意してください。

マップや配列などのマルチバリュー・フィールドはグルーピングに使用できます。ただし、そのようなフィールドに対してsum()などの集約関数を使用すると、誤解を招く結果になることがあります。文字列から整数へのマップ(`map<string, int>`)があり、文字列がグルーピングに使用する何らかのキーであると仮定します。次の式は、すべてのキーの値の合計を返します:

```bash
all( group(mymap.key) each(output(sum(mymap.value))) )
```

これは、期待されるような各キー内の値の合計ではありません。ただし、次の式を実行すれば、特定のキー内の値の合計を得ることは可能です:

```
all( group("my_group") each(output(sum(mymap{"foo"}))) )
```

その他の例については、[構造体型およびマップ型に対するグルーピング](https://github.com/vespa-engine/system-test/blob/master/tests/search/struct_and_map_types/struct_and_map_grouping.rb)のシステムテストを参照してください。
