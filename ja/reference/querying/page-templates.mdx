このドキュメントは、Page Template XML フォーマットの要素のリファレンスです。[ページ・テンプレート入門](/ja/querying/page-templates)を参照してください。

ページ・テンプレートは、ページ上でいくつかのソースからのデータを構成する特定の方法(または方法の集合)を記述します。次のような構造を持ちます:

<Card>
`<`[page](#page) id="[\[id\]](#id)"> *`<!-- The top-level section of this page -->`* 
&ensp;&ensp;\[page-element\]\* 
`</page>`
</Card>

...ここで、各 `[page-element]` は以下のいずれかです:

\<[section](#section)\>[page-element]\*\</section\>

_ネストされたセクション(画面領域)_

\<[source](#source) name="[source-name]"\> [renderer]\* [parameter]\* \</source\>

_このセクションに配置されるべきデータ・ソース_

\<[renderer](#renderer) name="[renderer-name]"\> [parameter]\* \</renderer\>

_これを含むソースまたはセクションに使用するレンダラー_

\<[choice](#choice)\> [map] or [page-element]/[alternative]\* \</choice\>

_実行時に解決される、代替のページ要素間の選択_

\<placeholder id="[id]"/\>

_実行時に map の item によって置き換えられる要素_

\<[include](#include) idref="[page-id]"\>/\>

_別のページに含まれるページ要素をインクルードします_

上記のネストされた要素は以下のとおりです:

\<parameter name="[name]"\>[value]\</parameter\>

_それを保持する要素のパラメーター。レンダラーのパラメーターは、結果の中でそのままフロントエンドに送信されます。ソースのパラメーターは、クエリー・パラメーター `source.[sourceName].[name]` を設定することでソースに送信されます。_

\<alternative\> [page-element]\* \</alternative\>

_1 つの選択肢を構成する複数のページ要素_

\<[map](#map) to="placeholder-id1 placeholder-id2 ... "\> [page-element]/[item]\* \</alternative\>

_いくつかのページ要素のプレースホルダーへのマッピング_

\<[item](#item)\> [page-element]\* \</item\>

_すべてが 1 つのプレースホルダーにマップされるべき複数のページ要素_

すべてのタグには、タグの用途を文書化するための `description` 属性を含めることもできます。タグと属性の詳細は以下で説明します。

## id

id は次の形式を持ちます:

```bash
id        ::= name(:major(.minor(.micro(.qualifier)?)?)?)?
name      ::= identifier
major     ::= integer
minor     ::= integer
micro     ::= integer
qualifier ::= identifier
```

省略された数値のバージョン・コンポーネントは 0 を意味するものとみなされ、qualifier の省略は空文字列を意味するものとみなされます。

## page

ページ・テンプレートのルート・タグです。ページを定義し、そのルート・セクションでもあります。属性とサブタグは [section](#section) と同じですが、page では `id` 属性が必須である点が異なります。

## section

画面領域の表現です。実行時に、セクションはさまざまなソースからのコンテンツを含みます。最終的なレンダラーは、それを含むタグによって決定される画面領域に、セクションとそのデータ・アイテムやサブセクションをレンダリングします。

## source

そのデータが、これを含むセクションに配置されるべきデータ・ソースです。

<table className="vespa-table">
  <thead>
    <tr>
      <th>属性</th>
      <th>説明</th>
      <th>デフォルト</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>name</td>
      <td>このソースの名前。</td>
      <td>_必須_</td>
    </tr>
    <tr>
      <td>url</td>
      <td>このソースの url。これが設定されている場合、このソースのデータは取得*されず*、代わりに(url 付きの)source タグが返されるページに現れ、フロントエンドがそれを取得できるようにします。このようなデータは、返されるページを最適化するために検査・処理することができないため、これは主に移行パスとして提供されています。</td>
      <td>_url なし: 設定されたこのソースをコンテナーから取得します。_</td>
    </tr>
  </tbody>
</table>

## renderer

特定のタイプのデータ・アイテム(ヒット)のセクションをレンダリングするために使用するレンダラーです。

  <thead>

      <th>説明</th>
      <th>デフォルト</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>name</td>
      <td>このレンダラーの名前。</td>
      <td>_必須_</td>
    </tr>
    <tr>
      <td>for</td>
      <td>これがレンダラーとなるヒット・タイプまたはソースの名前。</td>

    </tr>
  </tbody>

source 内の場合: これはこのソースからのヒットのデフォルト・レンダラーです。_ |

## choice

複数の代替の(リストの)ページ要素間の選択です。リゾルバーが、実行時にリクエストごとに可能な選択肢の中から選択します。`alternative` タグは選択肢を囲むために使用します。選択肢がページ要素タグ 1 つだけで構成される場合、それを囲む alternative タグは省略できます。

    </tr>

      <td>_任意の方法_</td>

  </tbody>
</table>

## map

choice のすべての選択肢を、要素からプレースホルダーへのマッピング関数として指定します。map は、各プレースホルダーが一意な要素を受け取るという制約のもとで、要素のコレクションをプレースホルダーの集合にマップすべき場合に、多数の選択肢を書くことの便利な短縮記法です。これは、たとえばソースの集合をセクションの集合にマップする場合に有用です。

## include

指定されたページ・テンプレートの `page` 要素に直接含まれるページ要素をインクルードします(page タグ自体はインクルードされません)。インクルードは、`include` タグがインクルードされるページの内容にそのまま置き換えられた場合とまったく同じように機能します。

    </tr>
  </thead>
  <tbody>
    <tr>
      <td>idref</td>
      <td>インクルードするページの id 指定。バージョンの一部を未指定のままにして、一致する最新のバージョンを取得できます。</td>
      <td>_(必須)_</td>
    </tr>
  </tbody>
</table>
