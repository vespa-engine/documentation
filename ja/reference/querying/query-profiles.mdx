これは、[クエリープロファイル](#query-profiles)および[クエリープロファイル・タイプ](#query-profile-types)の設定ファイルの完全なフォーマットのリファレンスです。クエリープロファイルの入門については、[クエリープロファイル](/ja/querying/query-profiles)を参照してください。

## クエリープロファイル

クエリープロファイルは、値を持つ検索リクエストパラメーターの名前付きセットを定義します - 構造:

```xml
<query-profile id="[[id]]" [[optional attributes]]>
  <description></description>?
  <dimensions></dimensions>?

  <field name="[[name]]" [[optional attributes]]>
    [[value]]
  </field>*

  <query-profile for="[[dimension values]]" [[optional attributes]]>
    <field name="[[name]]">[[value]]</field>*
  </query-profile>*

</query-profile>
```

ここで、`?` はオプション、`*` は繰り返し可能なタグを意味します。これらの項目については、以降のセクションで説明します。

### id

id のフォーマットは次のとおりです:

<Card>
id ::= name(:major(.minor(.micro(.qualifier)?)?)?)?<br/>
name ::=_[identifier](#identifiers)_<br/>
major ::=_integer_<br/>
minor ::=_integer_<br/>
micro ::=_integer_<br/>
qualifier ::=_[identifier](#identifiers)_
</Card>

省略された数値のバージョンコンポーネントは 0 を意味するものとみなされ、qualifier が省略された場合は空文字列を意味するものとみなされます。名前がちょうど `default` である場合、このプロファイルがデフォルトになります。`default` という名前のプロファイルが複数ある場合は、最も新しいバージョンがデフォルトになります。

### Description

このプロファイルの目的のテキストによる説明。ドキュメント化のために使用されます。

### クエリープロファイルの `field`

クエリープロファイルのフィールドは、キーと値のペアを定義します。

値がプリミティブ(文字列、数値)の場合、このキーと値は、検索リクエストのパラメーターとして送信された場合とまったく同じように Query から利用できます(両方の方法で設定された場合、検索リクエストが優先されます)。

値が別のクエリープロファイルへの参照である場合、参照先プロファイルのキーと値は、検索リクエストのパラメーターとして送信された場合とまったく同じように Query から利用できます。その際、ネストされたプロファイル内の各キーの前に、この値のキーとドットが付加されます。すなわち `keyNameInReferringProfile.keyNameInReferencedProfile=value` となります。

### `field` の name

フィールドの名前。有効な[識別子](#identifiers)でなければなりません。

### `field` の value

フィールドの値は、次のいずれかです:

- 任意の(XML エスケープされた)文字列としてエンコードされたプリミティブ、または
- \<ref\>[query-profile-id]\</ref\> としてエンコードされた別のクエリープロファイルへの参照

このフィールドが、このクエリープロファイルが参照するクエリープロファイル・タイプで定義されている場合、値はそのクエリータイプのフィールド定義で定義された有効な値の型でなければなりません。

### Dimensions

このプロファイルのバリアントを[ネストされたクエリープロファイル](#query-profile-nested)として作成できるディメンションのカンマ区切りリスト。ディメンションの名前は、リクエストパラメーターの名前であり、リクエストで受信されると、マッチするプロファイルバリアントをトリガーします。

### クエリープロファイル(ネスト)

ネストされたクエリープロファイルは、外側のクエリープロファイルから返される値のバリアントを定義します。これらは、[for 属性](#query-profile-nested-for-attribute)で定義されたとおり、このバリアントが[ディメンション](#dimensions)で指定されたリクエストプロパティに対して最も具体的にマッチする可変リクエストに対して返されます。ネストされたクエリープロファイルには、他の属性を設定することはできません。

### クエリープロファイル(ネスト)の `for` 属性

この属性は、このネストされたプロファイルが代替値を定義する、外側のプロファイルの[ディメンション](#dimensions)の値を、カンマ区切りリストとして定義します。値は、ディメンションが定義されたのと同じ順序で定義されます。任意の値にマッチさせたいディメンションは "\*" で表すことができます。末尾の 1 つ以上の "\*" は省略できます - 例:

<Card>
for="a,b,*,c,*,*"
for="a,b,*,c" // equivalent to the above
</Card>

## クエリープロファイル・タイプ

クエリープロファイル・タイプは、クエリープロファイルの有効で型付けされた値のセットを定義します - 構造:

```xml
<query-profile-type id="[[id]]" [[optional attributes]]>

    <description></description> ?

    <match path="true"/> ?

    <strict/> ?

    <field name="[[name]]" type="[[type]]" [[optional attributes]]/> *

</query-profile-type>
```

ここで、`?` はオプションのタグ、`*` は繰り返し可能なタグを意味します。これらの項目については、以降のセクションで説明します。

### `match`

クエリープロファイル・タイプに \<match path="true"\> を追加すると、クエリープロファイル名を実際のプロファイルにマッチングする際に、プロファイルの名前はスラッシュ区切りのパス名として解釈されます。クエリープロファイル名が、クエリープロファイル名の参照の _パスコンポーネントのプレフィックス_ である場合、そのプロファイルは参照にマッチします。最も具体的にマッチするプロファイルが参照のターゲットとして使用されます。

プロファイル・タイプで `match` が指定されていない場合は、完全な名前のマッチングが使用されます。この構文は、将来の拡張のために規定されたとおりです。

match 設定は、スーパータイプからサブタイプに継承されます。

### `strict`

この要素をクエリープロファイル・タイプに追加すると、そのプロファイルには、プロファイルで明示的に定義された値のみを含めることができます。値がクエリープロファイル、検索リクエスト、またはプログラムのいずれによって提供される場合でも同様です。

strict でないプロファイルに strict なサブプロファイルを追加したり、その逆も可能であり、それぞれ「マップ内の構造体」と「構造体内のマップ」を作成できます。

strict なプロファイルを継承するプロファイルも strict になります。すなわち `strict` は継承されます。

strict として宣言されたトップレベルのプロファイル・タイプを使用する際に注意すべきいくつかのルール:

  - トップレベルのプロファイルが strict なタイプの場合、組み込みパラメーターを渡せるようにするために、そのタイプは通常 `native` タイプを継承すべきです。このプロファイル・タイプとそれが参照するサブタイプは常に利用可能です - [Query API リファレンス](/ja/reference/api/query)を参照してください。
  - トップレベルのプロファイルが strict であっても、プリミティブでないモデルオブジェクトはクエリープロファイルに追加できますが、プリミティブ(文字列、数値、ブーリアン)は許可 _されず_、strict なプロファイル・タイプで宣言するか、適切なモデルオブジェクトでラップする必要があります
  - `select` のような機能固有のプロパティは自動的には許可されません。公開すべき機能のパラメーターは、strict なトップレベルのタイプで明示的に宣言する必要があります。

### 識別子

識別子は、パターン `[a-zA-Z_/][a-zA-Z0-9_/]*` にマッチする文字列です。
