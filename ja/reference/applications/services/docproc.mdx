これは [services.xml](/ja/reference/applications/services/services) における [document-processing](/ja/applications/document-processors) のリファレンスです:

```yaml expandable
container
    document-processing [numnodesperclient, preferlocalnode, maxmessagesinqueue, maxqueuebytesize,
                         maxqueuewait, maxconcurrentfactor, documentexpansionfactor, containercorememory]
        include
        documentprocessor [class, bundle, id, idref, provides, before, after]
            provides
            before
            after
            map
                field [doctype, in-document, in-processor]
        chain [name, id, idref, inherits, excludes, documentprocessors]
            map
                field [doctype, in-document, in-processor]
            inherits
               chain
               exclude
            documentprocessor [class, bundle, id, idref, provides, before, after]
                provides
                before
                after
                map
                    field [doctype, in-document, in-processor]
            phase [id, idref, before, after]
                before
                after
        threadpool
```

## Document Processor 要素

*documentprocessor* 要素は、[docproc chain 要素](#chain)または *document-processing* ルートに含まれます。

documentprocessor 要素は、ドキュメント・プロセッサーの定義またはドキュメント・プロセッサーの参照のいずれかです。このセクションの残りの部分ではドキュメント・プロセッサーの定義を扱います。ドキュメント・プロセッサーの参照については [docproc chain 要素](#docproc-chain-elements)で説明します。

documentprocessor の定義により、ちょうど 1 つのドキュメント・プロセッサー・インスタンスが作成されます。このインスタンスは、documentprocessor 要素の内容に従ってセットアップされます。

docproc chain 要素に含まれる documentprocessor の定義は、*内部(inner)ドキュメント・プロセッサー*を定義します。それ以外の場合は、*外部(outer)ドキュメント・プロセッサー*を定義します。

内部 documentprocessor の場合、名前は docproc chain 内で一意でなければなりません。外部 documentprocessor の場合、コンポーネント id は一意でなければなりません。内部 documentprocessor が外部 documentprocessor と同じ名前を持つことは許可されません。

省略可能なサブ要素:

- provides: provides リストに追加する単一の名前
- before: before リストに追加する単一の名前
- after: after リストに追加する単一の名前
- config(1 つ以上)

provides、before、after の詳細については、[チェーン化されたコンポーネント](/ja/applications/chaining)を参照してください。

### documentprocessor

ユーザーが指定したクラスの documentprocessor インスタンスを定義します。

```xml
<documentprocessor id="componentId"
                   class="className:versionSpecification"
                   bundle="the name in <artifactId> in pom.xml">
    ...
</documentprocessor>
```

## Docproc chain 要素

docproc chain をどのようにインスタンス化するか、および含まれるドキュメント・プロセッサーをどのように順序付けるかを指定します。

### chain

*document-processing* に含まれます。[chain リファレンス](/ja/reference/applications/services/processing#chain)を参照してください。チェーンは他のチェーンからドキュメント・プロセッサーを[継承](/ja/reference/applications/services/processing#inherits)でき、順序付けに[フェーズ](/ja/reference/applications/services/processing#phase)を使用できます。省略可能なサブ要素:

- [documentprocessor 要素](#documentprocessor)(1 つ以上)。documentprocessor 参照または documentprocessor 定義のいずれか。documentprocessor に指定された名前が*外部 documentprocessor* に一致する場合は *documentprocessor 参照*であり、そうでない場合は *documentprocessor 定義*です。documentprocessor 定義である場合、それは同時に「*正確に*この documentprocessor を使用する」という暗黙的な documentprocessor 参照でもあります。これらの documentprocessor 要素はすべて異なる名前を持たなければなりません。
- [phase](/ja/reference/applications/services/processing#phase)(1 つ以上)。
- [config](/ja/reference/applications/config-files#generic-configuration-in-services-xml)(1 つ以上。この docproc chain 内のすべての*内部* documentprocessor に適用されます。ただし、個々の内部 documentprocessor でオーバーライドされた場合を除きます)。

## Map

入力ドキュメント内のフィールド名から、デプロイされた docproc で使用される名前へのフィールド名マッピングをセットアップします。目的は、フィールド名を変更することなく機能を再利用することです。以下の例は設定を示しています:

```xml
<chain name="myChain">
    <map>
        <field in-document="key" in-processor="id"/>
    </map>
    <documentprocessor type="CityDocProc">
        <map>
            <field in-document="town" in-processor="city" doctype="restaurant"/>
        </map>
    </documentprocessor>
    <documentprocessor type="CarDocProc">
        <map>
            <field in-document="engine.cylinders" in-processor="cyl"/>
        </map>
    </documentprocessor>
</chain>
```

この例では、2 つの docproc を持つチェーンがデプロイされます。

チェーンに対しては、*key* から *id* へのマッピングがセットアップされます。チェーン内の一部またはすべての docproc が *id* というフィールドを読み書きするものの、この機能をドキュメント・フィールド *key* に対して使いたい、という状況を想像してください。

さらに、`CityDocProc` に対しても同様のことが行われます。この docproc はフィールド *city* にアクセスしますが、フィードでは *town* と呼ばれています。このマッピングはドキュメント・タイプ *restaurant* にのみ適用されます。

`CarDocProc` は *cyl* というフィールドにアクセスします。この例では、ドット記法を使用して、struct *engine* のフィールド *cylinders* にマップされています。

設定の異なるレベルでマッピングを指定した場合(たとえばクラスターと docproc の両方)、実際の docproc に最も近いマッピングが優先されます。

## threadpool

`Vespa 8.601.12` 以降で利用可能

ドキュメント・プロセッサーのチェーンが使用するスレッド・プールの設定を指定します。すべての値は vCPU 数に応じてスケールします。[コンテナー・チューニングの例](/ja/performance/container-tuning#container-worker-threads-example)を参照してください。すべてのワーカーがビジー状態の場合、新しいドキュメント処理リクエストは拒否されます。

### threads

vCPU あたりのワーカー・スレッド数。デフォルト値は `1` です。プールは `threads * vCPU` のワーカーで動作します。
