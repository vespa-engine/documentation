<table className="vespa-table">
  <thead>
    <tr>
      <th>状態</th>
      <th>説明</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><code>{`Up`}</code></td>
      <td>ノードは稼働しており、バケットを保持しリクエストを処理できます。</td>
    </tr>
    <tr>
      <td><code>{`Down`}</code></td>
      <td>ノードは利用できず、使用できません。</td>
    </tr>
    <tr>
      <td><code>{`Stopping`}</code></td>
      <td>このノードは停止処理中であり、まもなくダウンすることが予想されます。この状態は通常、ノードが停止した理由を伝えるためにクラスターコントローラーに対してのみ公開されます。クラスターコントローラーは、クラスターの他の部分に対してこのノードをダウンまたはメンテナンスモードとして公開します。したがって、この状態は分散アルゴリズムからは見えません。</td>
    </tr>
    <tr>
      <td><code>{`Maintenance`}</code></td>
      <td>このノードは一時的に利用できません。ノードはバケット配置の対象として利用可能なままであるため、冗長性は低下します。このモードを使用すると、このノードに保存されているドキュメントの新しいレプリカは作成されず、クラスターの他の部分へのパフォーマンス影響を抑えつつノードをダウンさせることができます。このモードは通常、制御されたノード再起動中にダウン状態をマスクするため、またはソフトウェアのアップグレードやノードの再起動といった短時間のメンテナンス作業を行う必要がある管理者によって使用されます。</td>
    </tr>
    <tr>
      <td><code>{`Retired`}</code></td>
      <td>リタイア状態のノードは利用可能で、リクエストを処理します。この状態は、冗長性を維持しながらノードを削除するために使用されます。バケットは空になるまで（低い優先度で）他のノードに移動されます。<a href="/ja/content/elasticity#grouped-distribution" aria-label="grouped distribution">グループ化分散</a>を使用している場合は、バケットが必ずしも削除されるとは限らないため、特別な考慮が必要です。</td>
    </tr>
  </tbody>
</table>

      <td>クラスターコントローラーは、すべてのノードから状態を取得します。これは&#42;ユニット状態&#42;と呼ばれます。ノードから報告される状態は <code>{`up`}</code> または <code>{`stopping`}</code> のいずれかです。ノードに到達できない場合は、<code>{`down`}</code> 状態と見なされます。つまり、クラスターコントローラーが障害ノードを検出します。その後の&#42;生成状態&#42;ではノードは <code>{`down`}</code> となり、<a href="/ja/content/idealstate" aria-label="ideal state algorithm">理想状態アルゴリズム</a>がドキュメントの<a href="/ja/content/buckets" aria-label="buckets">バケット</a>を再分散します。</td>

      <td><a href="/ja/operations/self-managed/admin-procedures#cluster-state" aria-label="user state management">ユーザー状態管理</a>用のツールを使用してください。クラスターからノードをリタイアさせる - <code>{`retired`}</code> を使用してバケットを他のノードに移動します。短時間のメンテナンス作業 - <code>{`maintenance`}</code> を使用して、バケットが他のノードにマージされるのを防ぎます。不良ノードの停止。クラスターコントローラーまたはオペレーターは、ノードを <code>{`down`}</code> に設定できます</td>
