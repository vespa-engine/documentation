コンテナー・クラスターがどのコンポーネントをホストするかは services.xml で設定します。JDIsc の主な機能は次のとおりです:

- 組み込みの Jetty サーバーによるすぐに使える HTTP サービングと、他のトランスポート機構をプラグインするためのサポート。
- Vespa の設定システムとの統合。これにより、コンポーネントはアプリケーションのデプロイによって生成される[最新の設定を受け取る](/ja/applications/configuring-components)ことができます(コンストラクター・インジェクションによる)。
- [Guice に基づく依存性注入](/ja/applications/dependency-injection)(Felix)。ただし、設定とコンポーネント・コレクション向けに拡張されています。
- [OSGi](/ja/applications/bundles) に基づくコンポーネント・モデル。これにより、コンポーネントを稼働中のサーバーに(再)デプロイでき、他のコンポーネントに公開する API を制御できます。
- 上記の機能を組み合わせることで、アプリケーション・パッケージの変更(コンポーネント、設定、またはデータの変更)を、リクエストのサービングを妨げることなく、また再起動を必要とせずに Vespa が適用できます。
- 次の用途のための標準コンポーネント・タイプが存在します:
    - [汎用的なリクエスト処理](/ja/applications/request-handlers)
    - [チェーン化されたリクエスト・レスポンス処理](/ja/applications/processing)
    - [ドキュメント書き込みの処理](/ja/applications/document-processors)
    - [クエリーと結果のインターセプト](/ja/applications/searchers)
    - [レスポンスのレンダリング](/ja/applications/result-renderers)

    アプリケーション・コンポーネントはその他の任意のタイプでもよく、コンテナーによってロード・管理されるために Vespa の API を参照する必要はありません。
- コンポーネントのための汎用的な[チェーン構成](/ja/applications/chaining)機構。

## コンポーネントの開発

- JDisc コンテナーは、*Processing* という名前のリクエストとレスポンスを処理するためのフレームワークを提供します。その構成要素は次のとおりです:
    - 直列に実行される他のコンポーネントの[チェーン](/ja/applications/chaining)。各コンポーネントは何らかのサービスまたは変換を提供します
    - リクエストやレスポンスを変更する[プロセッサー](/ja/applications/processing)。プロセッサーは、直列または並列に複数のフォワード・リクエストを行ったり、レスポンスのコンテンツ自体を生成したりすることもできます
    - プロセッサーのレスポンスをクライアントに返す前にシリアライズするために使われる[レンダラー](/ja/applications/processing#response-rendering)
- アプリケーションのライフサイクルとユニット・テスト:
    - カスタム設定による[コンポーネントの設定](/ja/applications/configuring-components)
    - [コンポーネント・インジェクション](/ja/applications/dependency-injection)により、コンポーネントは他のアプリケーション・コンポーネントにアクセスできます
    - [OSGi バンドルのビルド方法](/ja/applications/bundles)と、クラスローディングの問題の[トラブルシューティング](/ja/applications/bundles#troubleshooting)方法を学びます
    - コンポーネントから[プラガブル・フレームワーク用のライブラリー](/ja/applications/pluggable-frameworks)を使用すると、アプリケーションで追加のセットアップが必要となるクラスローディングの問題が発生する場合があります
    - [設定可能なコンポーネントのユニット・テスト](/ja/applications/unit-testing#unit-testing-configurable-components)
- ハンドラーとフィルター:
    - HTTP および HTTPS での受信接続のための [HTTP サーバーとセキュリティー・フィルター](/ja/applications/http-servers-and-filters)
    - 受信リクエストを処理してレスポンスを生成する[リクエスト・ハンドラー](/ja/applications/request-handlers)
- サーチャーとドキュメント・プロセッサー:
    - [サーチャー](/ja/applications/searchers)と[検索結果レンダラー](/ja/applications/result-renderers)の開発
    - [ドキュメント処理](/ja/applications/document-processors)
