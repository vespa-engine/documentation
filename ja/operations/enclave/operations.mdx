Vespa Cloud Enclave では、VPC 内にプロビジョニングされたリソースは Vespa Cloud のオーケストレーションサービスによって完全に管理される必要があり、テナントの運用担当者が手動で管理してはなりません。Configuration Server によって作成されたリソースを変更または削除すると、Vespa アプリケーションに悪影響を及ぼし、Vespa Cloud によるアプリケーションの適切な管理や、Vespa エンジニアによるサポートが妨げられる可能性があります。

Terraform モジュールは、後方互換性のある更新が随時行われることがあります。テナントは定期的にシステムへ更新を適用することを推奨します。詳細については、Terraform ドキュメントの [using Terraform in automation](https://developer.hashicorp.com/terraform/tutorials/automation/automate-terraform) を参照してください。

Vespa アプリケーションが正常に動作するためには、Vespa Host に付与されたネットワークアクセスが維持されている必要があります。ネットワークアクセスが制限されると、Vespa アプリケーションが動作しなくなる可能性があります。

## カスタムリソースタグ

Vespa Cloud がテナントのクラウドアカウント内にプロビジョニングするクラウドリソース (仮想マシンとディスク) に、カスタムタグを適用できます。タグは *deployment.xml* の [`<resource-tags>`](/ja/reference/applications/deployment#resource-tags) 要素で宣言し、一般的にコスト追跡やリソース管理に使用されます。これは AWS、Azure、GCP でサポートされています。

## クォータ

一般的な Vespa Cloud のユースケースに対応できるよう、組織の AWS または GCP のクォータが十分に高く設定されていることを確認してください。よくあるユースケースとして新しいインスタンスタイプへの移行があり、この場合、データ移行の移行期間中はリソース使用量が一時的に 2 倍 (またはそれ以上) になります。その他に、一時的にリソース使用量が増加するユースケースとしてノードの交換があります。

ベストプラクティスは、キャパシティー拡張にも対応できるよう、クォータを現在のリソース使用量の 3 倍にしておくことです。

これは [Vespa Cloud のクォータ](/ja/cloud/quota)とは別のものですので、混同しないでください。
