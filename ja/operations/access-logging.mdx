Vespa のアクセスログのフォーマットは、JSON ベースの(ログ)ファイルを扱う数多くの既存ツールでログを処理できるようにしています。任意の Searcher からカスタムのキー/値ペアをログに追加できるため、特定のリクエストに対してコンテナー・コンポーネントが行った判断を簡単に追跡できます。

## Vespa アクセスログのフォーマット

### リモートアドレス/ポートのログ記録

リクエストが中間サービスを経由する場合、そのサービスが実際の送信元クライアントの IP アドレスとポートを示す HTTP ヘッダーを追加することがあります。これらの値はそれぞれ *remoteaddr* と *remoteport* として記録されます。Vespa は、次のいずれかの HTTP リクエストヘッダーの内容を *remoteaddr* として記録します: *X-Forwarded-For*、*Y-RA*、*YahooRemoteIP*、*Client-IP*。これらのヘッダーが複数存在する場合の優先順位はここに挙げた順であり、つまり *X-Forwarded-For* が *Y-RA* より優先されます。*Y-RP* HTTP リクエストヘッダーの内容は *remoteport* として記録されます。

リモートのアドレスやポートが HTTP リクエストを開始したものと異なる場合、リクエストを行った直接のクライアントのアドレスとポートはそれぞれ *peeraddress* と *peerport* として記録されます。

## ログの設定

アクセスログの設定の詳細は、*services.xml* の [container 内の accesslog](/ja/reference/applications/services/container#accesslog) 要素を参照してください。

主な設定オプションには次のものがあります:

- **fileNamePattern**: 時間変数をサポートするログファイル名のパターン
- **rotationInterval**: 時間ベースのローテーションスケジュール(深夜 0 時からの分数)
- **rotationSize**: サイズベースのローテーションのしきい値(バイト、0 = 無効)
- **rotationScheme**: 'sequence' または 'date' のいずれか
- **compressionFormat**: ローテーションされたファイルの GZIP または ZSTD 圧縮

### リクエスト内容のログ記録

Vespa は、特定の URI パスに対するリクエスト内容のログ記録をサポートしています。これは、検索 POST リクエストのクエリー内容や、Document v1 の POST/PUT リクエストのドキュメント操作を調べるのに便利です。リクエスト内容は、JSON アクセスログに base64 エンコードされた文字列として記録されます。

リクエスト内容のログ記録を設定するには、*services.xml* の accesslog 設定内の [request-content](/ja/reference/applications/services/container#request-content) 要素を使用します。

JSON アクセスログでリクエスト内容がどのように表示されるかの例を次に示します:

```json
{
  ...
  "method": "POST",
  "uri": "/search",
  ...,
  "request-content": {
    "type": "application/json; charset=utf-8",
    "length": 12345,
    "body": "<raw bytes encoded with base64>"
  }
}
```

## ログのローテーション

*rotationScheme* を設定することで、Apache httpd スタイルのログ*ローテーション*を設定できます。rotationScheme には sequence と date の 2 つの選択肢があります。ローテーションは、*rotationInterval* による時間間隔、および/または *rotationSize* によるファイルサイズでトリガーできます。

### sequence ローテーションスキーム

*fileNamePattern* はアクティブなログファイル名に使用されます(この場合、多くは固定の文字列になります)。ローテーション時に、このファイルには fileNamePattern.N という名前が付けられます。N は、同じディレクトリ内で .`<Integer>` で終わるすべてのファイルから整数を抽出して見つかった最大の整数に 1 を加えた値です。

```xml
<accesslog type='json'
           fileNamePattern='logs/vespa/access/JsonAccessLog.<container id>.%Y%m%d%H%M%S'
           rotationScheme='sequence' />
```

### date ローテーションスキーム

ここでも *fileNamePattern* はアクティブなログファイル名に使用されますが、ローテーション時にログファイルの名前は変更されません。代わりに、新しいログファイルが作成されるたびに名前が一意になるように、時刻に依存する fileNamePattern を指定する必要があります。さらに、アクティブなログファイルを指すシンボリックリンクが作成されます。シンボリックリンクの名前は *symlinkName* で指定します。

```xml
<accesslog type='json'
           fileNamePattern='logs/vespa/access/JsonAccessLog.<container id>.%Y%m%d%H%M%S'
           rotationScheme='date'
           symlinkName='JsonAccessLog' />
```

### ローテーション間隔

ローテーションの時刻は *rotationInterval* を設定して制御します:

```xml
<accesslog type='json'
           fileNamePattern='logs/vespa/access/JsonAccessLog.<container id>.%Y%m%d%H%M%S'
           rotationInterval='0 60 ...'
           rotationScheme='date'
           symlinkName='JsonAccessLog.<container id>' />
```

rotationInterval は、いつローテーションを行うかを指定する数値のリストです。各要素は深夜 0 時からの分数を表します。リストの末尾を「...」で終えると、最後の 2 つの数値で定義される[等差数列](https://en.wikipedia.org/wiki/Arithmetic_progression)がその日の残りの時間まで継続されることを意味します。たとえば「0 100 240 480 ...」は「0 100 240 480 720 960 1200」に展開されます。

### ログの保持

アクセスログはローテーションされますが、Vespa のプロセスによって削除されることはありません。アクセスログのアーカイブはアプリケーションの所有者の責任です。

## Searcher から JSON アクセスログへのキー/値ペアの記録

Searcher からアクセスログにキー/値ペアを追加するには、次を使用します

```bash
query/result.getContext(true).logValue(key,value)
```

このようなキー/値ペアは、同期のオーバーヘッドを発生させることなく、クエリー処理に参加している任意のスレッドから追加できます。

同じキーが複数回記録された場合、書き込まれた値は単一の文字列値ではなく、文字列の配列としてログに含まれます。

キー/値ペアは、ログの *attributes* オブジェクトに追加されます。

その場合のログ行の例は次のようになります:

```json
{"ip":"152.200.54.243","time":920880005.023,"duration":0.122,"responsesize":9875,"code":200,"method":"GET","uri":"/search?query=test&param=value","version":"HTTP/1.1","agent":"Mozilla/4.05 [en] (Win95; I)","host":"localhost","search":{"totalhits":1234,"hits":0},"attributes":{"singlevalue":"value1","multivalue":["value2","value3"]}}
```

同じ例を整形表示したもの:

