---
title: "手順: attributeからindexへの変更"
sidebarTitle: "attributeからindexへの変更手順"
---

`index` と `attribute` の間の変更は、パフォーマンスを最適化するための一般的なフィールド変更操作です。インデックス構造との間で安全にデータを移行するには、[再インデックス](/ja/operations/reindexing)機能を使用します。

attributeからindexへの変更は、「attributeの削除」と「indexの追加」と見なせます。フィールドのattributeの側面が削除されると、デプロイ後、そのフィールドのデータはクエリーできなくなります。再インデックスのプロセスがフィールドのインデックス構造にデータを投入しますが、これにはコーパスのサイズに応じた時間がかかります。

もう1つのアプローチは、移行期間中attributeとindexの両方で運用し、データをクエリー可能な状態に保つことです。この手順の要点は、`index` を追加し、再インデックスを実行してから、`attribute` の側面を削除することです:

```js
# field configuration at start
field artist type string {
    indexing: summary | attribute
}

->

# intermediate step to populate index structure, keeping the data in the attribute
field artist type string {
    indexing: summary | attribute | index
    match: word
    stemming: none
}

->

# final configuration, migrated to index
field artist type string {
    indexing: summary | index
    match: word
    stemming: none
}
```

<Note>
**注:** 

フィールドがフィルターとしてのみ使用される(つまりランキングに使用されない)場合は、`rank: filter` の追加を検討してください。[feature-tuning](/ja/performance/feature-tuning) の例を参照してください。
</Note>

## 手順

<Steps>
<Step>
[クイックスタート](/ja/basics/deploy-an-application-local)を使ってこれをテストします。実行前に `artist` フィールドをattributeに変更しておきます。また、`src/main/application/validation-overrides.xml` に[バリデーション・オーバーライド](/ja/reference/applications/validation-overrides)を追加します:

```xml
<validation-overrides>
    <allow until="2021-08-30">indexing-change</allow>
</validation-overrides>
```
</Step>
<Step>
クイックスタートを実行し、ドキュメントのフィード後に停止します。クエリーを実行して、データがクエリーできることを検証します:

```bash
$ curl "http://localhost:8080/search/?ranking=rank_albums&yql=select%20%2A%20from%20sources%20%2A%20where%20artist%20contains%20%22Coldplay%22"
```

[現在のインデックス構造をダンプ](#appendix)して、`artist` がattributeであることを確認することもできます。
</Step>
<Step>
フィールドにindexの側面とmatch/stemmingの設定を追加し、デプロイして出力を観察します

<Step>
この時点でインデックス構造をダンプすると、artistがindexとattributeの両方にあることが分かり、vespa.logにもエントリーがあります。クエリーがまだ動作することを検証します:

```bash
$ docker exec vespa /usr/bin/sh -c 'vespa-logfmt | grep Reindexer'
```

<Step>

```js
field artist type string {
    indexing: summary | index
        match    : word
        stemming : none
}

$ (cd src/main/application && zip -r - .) |   curl --header Content-Type:application/zip --data-binary @- \
  localhost:19071/application/v2/tenant/default/prepareandactivate

$ curl "http://localhost:8080/search/?ranking=rank_albums&yql=select%20%2A%20from%20sources%20%2A%20where%20artist%20contains%20%22Coldplay%22"
```

</Step>
<Step>
オプション: Vespaを再起動します - 再起動によりattributeからメモリーが回収されます:

```bash
$ docker exec vespa sh -c 'vespa-stop-services && vespa-start-services'
```
</Step>
</Steps>

注意事項:

- 上記のmatch/stemmingの設定は、attributeのデフォルト設定と同じ値に設定しています

## 付録

attributeとindexのデータを調べる(トラブルシューティング時に役立ちます)には、[vespa-proton-cmd](/ja/reference/operations/self-managed/tools#vespa-proton-cmd) を使用し、その後ファイルを一覧表示します:

```bash
$ docker exec vespa vespa-proton-cmd --local triggerFlush
$ docker exec vespa find /opt/vespa/var/db/vespa/search/cluster.music/n0/documents/music/0.ready
```
