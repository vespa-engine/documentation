私たちの経験上、Vespa について質問する際に良い結果を得るには、LLM に適切なコンテキストを提供することが不可欠です。

## ドキュメント・ページの Markdown 版

ドキュメントのすべてのページは、URL の `.html` を `.html.md` に変更することで、Markdown 形式で利用できます。各ページの右上にも Markdown 版へのリンクがあります。

これはたとえば、特定のトピックについて LLM を使って作業する際に、関連する Markdown ドキュメント・ページをお好みの AI ツールにコピー/ペーストするために使用できます。

## llms.txt

私たちは [llms.txt](https://docs.vespa.ai/llms.txt) ファイルを提供しています。これは LLM のトップレベルのエントリーポイントとして機能し、トップレベルの概要とアーキテクチャーに加えて、すべてのドキュメント・ページのタイトルと Markdown 版へのリンクを含みます。

この形式の詳細については [llmstxt.org](https://llmstxt.org/) を参照してください。

### 使用例

[llms.txt](https://docs.vespa.ai/llms.txt) ファイルは、次のコマンドでダウンロードできます:

```bash
curl -O /llms.txt
```

このファイルは、IDE、CLI、またはチャット・インターフェースを通じて LLM を使う際のエントリーポイントとして利用できます。LLM が参照先の URL を取得できるツールを持っている場合、必要に応じて目的のページの内容を取得できます。

また、すべてのドキュメント・ページの_全文_を Markdown 形式で含む [llms-full.txt](https://docs.vespa.ai/llms-full.txt) も提供しています。このファイルは比較的大きい(2025 年 10 月時点で約 50 万語)ため、用途に応じて使用してください。

## MCP サーバー

### パブリックな Vespa MCP サーバー

現時点では公式の [MCP](https://modelcontextprotocol.io/) サーバーは提供していませんが、提供を開始し次第このページを更新します。

### 個人用 MCP サーバー

ユーザーは、自分の Vespa アプリで MCP サーバー機能を有効にできます。これは、`services.xml` に `McpRequestHandler` を追加し、1 つ以上の `McpSpecProvider` コンポーネントを設定することで実現できます。

ビルド済みの `McpSearchSpecProvider` がすでに存在し、使用例は[このサンプル・アプリ](https://github.com/vespa-engine/sample-apps/tree/master/examples/mcp-server-app)にあります。これは、`/mcp/` エンドポイントを介して Vespa の検索を LLM に公開します。

ユーザーは、`McpSpecProvider` を実装して `services.xml` にコンポーネントを追加することで、さらにツールを追加できます。

#### MCP 設定の例

次を `services.xml` に追加します

```xml
<component id="com.yahoo.search.mcp.McpSearchSpecProvider" bundle="container-search-and-docproc"/>
<handler id="ai.vespa.mcp.McpRequestHandler" bundle="container-disc">
    <binding>http://*/mcp/*</binding>
</handler>
```
