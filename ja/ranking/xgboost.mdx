Vespa は、[XGBoost](https://xgboost.readthedocs.io/) で学習した勾配ブースティング決定木(GBDT)モデルのインポートをサポートしています。

## XGBoost からのモデルのエクスポート

Vespa は 2 つの XGBoost モデル形式をサポートしています: UBJ(推奨)と JSON(レガシー)です。

### UBJ 形式(推奨)

`Vespa 8.656.31+`

Vespa 向けに XGBoost モデルをエクスポートする推奨の方法は、`.ubj`(Universal Binary JSON)拡張子を付けて [`save_model()`](https://xgboost.readthedocs.io/en/latest/python/python_api.html#xgboost.Booster.save_model) を使用することです。UBJ は XGBoost 2.1.0 以降のデフォルトの XGBoost モデル形式であり、ツリー構造、`base_score`、特徴量名、objective といったすべてのモデル情報を保持します。


```python
import xgboost as xgb
import numpy as np

# Train a model
dtrain = xgb.DMatrix(np.random.rand(100, 2), label=np.random.randint(2, size=100),
                      feature_names=["feature_1", "feature_2"])
param = {"max_depth": 2, "objective": "binary:logistic"}
model = xgb.train(param, dtrain, num_boost_round=10)

# Export as UBJ
model.save_model("my_model.ubj")
```



<Warning>
**重要:**

`save_model("model.json")` は使用**しないでください** — これは(`learner` ラッパーを持つ)異なる JSON 構造を生成し、Vespa は解析できません。JSON の経路でサポートされているのは、`dump_format="json"` を指定した `dump_model()` のみです。
</Warning>


UBJ 形式は objective を保持するため、Vespa は正しい変換(たとえばロジスティック objective に対するシグモイド)を自動的に適用します — ランキング式を手動でラップする必要はありません。

### JSON 形式(レガシー)

Vespa は、`dump_format="json"` を指定した
[`dump_model()`](https://xgboost.readthedocs.io/en/latest/python/python_api.html#xgboost.Booster.dump_model)
による XGBoost の JSON モデルダンプのインポートもサポートしています。


```python
import xgboost as xgb

dtrain = xgb.DMatrix("training-vectors.txt")
param = {"base_score": 0, "max_depth": 1, "objective": "reg:squarederror"}
bst = xgb.train(param, dtrain, 2)
bst.dump_model("trained-model.json", fmap="feature-map.txt", with_stats=False, dump_format="json")
```


これは、ツリーオブジェクトの JSON 配列を生成します。


```json
[
  { "nodeid": 0, "depth": 0, "split": "fieldMatch(title).completeness", "split_condition": 0.772132337, "yes": 1, "no": 2, "missing": 1, "children": [
    { "nodeid": 1, "leaf": 0.673938096 },
    { "nodeid": 2, "leaf": 0.791884363 }
  ]},
  { "nodeid": 0, "depth": 0, "split": "fieldMatch(title).importance", "split_condition": 0.606320798, "yes": 1, "no": 2, "missing": 1, "children": [
    { "nodeid": 1, "leaf": 0.469432801 },
    { "nodeid": 2, "leaf": 0.55586201 }
  ]}
]
```


`split` 属性は Vespa の特徴量名を表し、[ドキュメントスキーマ](/ja/basics/schemas)で定義された Vespa の[ランク特徴量](/ja/reference/ranking/rank-features)、またはユーザー定義の[関数](/ja/ranking/ranking-expressions-features#function-snippets)に解決される必要があります。

学習データは [LibSVM テキスト形式](https://xgboost.readthedocs.io/en/latest/tutorials/input_format.html)で表現されます。`ranking` objective を使用した完全な [XGBoost 学習ノートブック](https://github.com/vespa-engine/sample-apps/blob/master/commerce-product-ranking/notebooks/Train-xgboost.ipynb)も参照してください。


<Warning>
**重要:**

`dump_model()` の JSON は `base_score` を保持**しません**。
学習時に `base_score=0` を設定するか、Vespa の予測値がオフセットされることを受け入れてください。
ロジスティック objective の場合は、式を手動で `sigmoid()` でラップする必要があります([objective の種類](#xgboost-objective-types)を参照)。
</Warning>


## XGBoost から Vespa への特徴量マッピング

モデルの特徴量名は、Vespa の[ランク特徴量](/ja/reference/ranking/rank-features)にマッピングされる必要があります。マッピング方法はモデル形式によって異なります。

### UBJ の特徴量マッピング

UBJ モデルの場合、`models` ディレクトリの `.ubj` ファイルの隣に、`<model_name>-features.txt` という名前の特徴量ファイルを配置します。このファイルには、学習時の列の順序に一致するように、1 行に 1 つの特徴量名を記述します。


```txt
feature_1
feature_2
feature_3
```


`my_model.ubj` という名前のモデルファイルの場合、特徴量ファイルの名前は `my_model-features.txt` である必要があります。

次に、特徴量名に一致するランクプロファイルの[関数](/ja/ranking/ranking-expressions-features#function-snippets)を定義し、Vespa のドキュメント属性またはクエリー特徴量にマッピングします。


```js
schema my_app {
    document my_app {
        field price type double {
            indexing: summary | attribute
        }
        field popularity type double {
            indexing: summary | attribute
        }
    }
    rank-profile my_rank_profile inherits default {
        function feature_1() {
            expression: attribute(price)
        }
        function feature_2() {
            expression: attribute(popularity)
        }
        function feature_3() {
            expression: query(user_context)
        }
        first-phase {
            expression: xgboost("my_model.ubj")
        }
    }
}
```


モデルが、有効な Vespa ランク特徴量(たとえば `attribute(price)`)である特徴量名で学習されている場合、これらの関数は不要です — Vespa が直接解決します。

### JSON の特徴量マッピング

`dump_model()` を使用する場合、特徴量マップファイル(`fmap`)が提供されない限り、XGBoost は特徴量を配列インデックス(`f0`、`f1`、...)で命名します。`fmap` は、特徴量のインデックスを名前付きの Vespa 特徴量にマッピングします。


```bash
$ cat feature-map.txt | egrep "fieldMatch\(title\).completeness|fieldMatch\(title\).importance"
36  fieldMatch(title).completeness q
39  fieldMatch(title).importance q
```


この例では、インデックス 36 の特徴量は [fieldMatch(title).completeness](/ja/reference/ranking/rank-features#fieldMatch(name).completeness) に、インデックス 39 は [fieldMatch(title).importance](/ja/reference/ranking/rank-features#fieldMatch(name).importance) にマッピングされます。

`feature-map.txt` の形式 `<featureid> <featurename> <q or i or int>\n`:
  - 特徴量 id は 0 から特徴量の数までで、ソートされた順序である必要があります
  - `i` は、この特徴量がバイナリのインジケーター特徴量であることを意味します
  - `q` は、この特徴量が年齢や時間のような量的な値であり、欠損しうることを意味します
  - `int` は、この特徴量が整数値であることを意味します(int がヒントとして与えられると、決定境界は整数になります)

列名付きの Pandas の `DataFrame` を使用する場合、特徴量名は JSON ダンプに直接埋め込まれるため、特徴量マップファイルは不要です。

## XGBoost モデルのインポート

XGBoost モデルをインポートするには、アプリケーション・パッケージの `models` ディレクトリの下にモデルファイルを追加します。UBJ モデルの場合は、対応する `-features.txt` ファイルも含めます。


```bash
├── models
│   ├── my_model.ubj
│   ├── my_model-features.txt
│   └── legacy_model.json
├── schemas
│   └── main.sd
└── services.xml
```


アプリケーション・パッケージは複数のモデルを持つことができます。

## XGBoost モデルによるランキング

Vespa には `xgboost` [ランキング特徴量](/ja/reference/ranking/rank-features)があります。このランキング特徴量は、ランキング式で使用するモデルを指定します。UBJ モデルと JSON モデルのどちらも同じランキング特徴量を使用します。


```js
schema my_app {
    rank-profile prediction inherits default {
        first-phase {
            expression: nativeRank
        }
        second-phase {
            expression: xgboost("my_model.ubj")
        }
    }
}
```


ここでは、first-phase のランキング式によって上位にランクされたドキュメントに、モデル `my_model.ubj` を適用するように指定しています。クエリーリクエストでは、[ranking.profile](/ja/reference/api/query#ranking.profile) として `prediction` を指定する必要があります。モデルに公開されるデータポイント/ドキュメントの数を制御する方法については、[フェーズドランキング](/ja/ranking/phased-ranking)も参照してください。

一般に、実行時の計算量は次によって決まります。

* [スレッドあたり](../performance/sizing-search.html)に評価されるドキュメント数 / ノード数とクエリーフィルター
* 特徴量計算の複雑さ。たとえば `fieldMatch` 特徴量は `nativeFieldMatch/nativeRank` の 100 倍高コストです。
* XGBoost のツリー数とツリーごとの最大深さ

サービングのレイテンシーは、[クエリーリクエストごとに複数のスレッドを使用する](/ja/performance/practical-search-performance-guide#multithreaded-search-and-ranking)ことで低減できます。

### 高速フォレスト評価

大規模なフォレストでは、代替の GBDT 評価器を使うことで評価コストをさらに削減できます。ランクプロファイルで [rank-property](/ja/reference/ranking/rank-feature-configuration) の `vespa.eval.use_fast_forest` を `true` に設定して有効にします。

```js
rank-profile prediction inherits default {
    rank-properties {
        vespa.eval.use_fast_forest: true
    }
    second-phase {
        expression: xgboost("my_model.json")
    }
}
```

これはランクプロファイルの設定であり、クエリーパラメーターではありません。モデルのコンパイル時に適用されるため、クエリーごとに切り替えることはできません。A/B テストを行うには、このプロパティのみを追加した 2 つ目のランクプロファイルを作成してください。

<Note>
高速フォレスト評価が適用されるのは、モデル内のすべての分割が数値(`<` またはその反転形)であり、どのツリーもリーフ数が 2,048 以下で、ルートの式がツリーの単純な総和である場合のみです。したがって、UBJ モデルは決して対象になりません。インポーターは常にツリーの総和に `base_score` を付加するためです。レガシーの JSON モデルは、`reg:squarederror` およびランキング objective では対象になりますが、式が別の関数でラップされている場合(たとえばロジスティック objective の `sigmoid(xgboost(...))`)は対象外です。これらのいずれの場合も、この設定は効果を持たず、Vespa は暗黙的にデフォルトの評価器にフォールバックします。
</Note>

高速化の度合いは、ツリー数よりもツリーごとのリーフ数に依存します。ツリーごとのリーフ数が最大 64 のモデルが最も恩恵を受けます。

## カテゴリカル特徴量


<Warning>
**重要:**

Vespa は XGBoost のネイティブなカテゴリカル分割(`enable_categorical=True`)をサポートして**いません**。ネイティブなカテゴリカル分割を持つモデルをデプロイすると、**気づかないうちに誤った予測が生成されます** — Vespa はカテゴリカル分割の条件を数値のしきい値として解釈します。
</Warning>


Vespa の XGBoost モデルでカテゴリカル特徴量を使用するには、学習の前に整数エンコードしてください。


```python
import xgboost as xgb
import pandas as pd

# Integer-encode categorical features
category_map = {"small": 0, "medium": 1, "large": 2}
df["size"] = df["size_raw"].map(category_map).astype(float)

# Train without enable_categorical — XGBoost uses numerical splits on the integers
dtrain = xgb.DMatrix(df[feature_cols], label=targets)
param = {"max_depth": 4, "objective": "binary:logistic"}
model = xgb.train(param, dtrain, num_boost_round=100)
model.save_model("my_model.ubj")
```


Vespa のスキーマでは、整数エンコードされたカテゴリカル値を `int` 属性として格納し、他の数値特徴量と同様に、ランクプロファイルの関数を通じてマッピングします。

注: Vespa の [LightGBM](/ja/ranking/lightgbm) インポーターは、ネイティブなカテゴリカル分割をサポートしています。

## XGBoost の objective の種類

Vespa は、任意の [objective](https://xgboost.readthedocs.io/en/stable/parameter.html#learning-task-parameters) で学習された XGBoost モデルをインポートできます。一般的な objective は次のとおりです。

* 回帰 `reg:squarederror` / `reg:logistic`
* 分類 `binary:logistic`
* ランキング `rank:pairwise`、`rank:ndcg`、`rank:map`

Vespa は、ツリーの出力を合計することで XGBoost モデルを評価します。objective 固有の動作はロジスティック objective(`reg:logistic` と `binary:logistic`)に対するものだけで、この場合、確率を生成するには生のツリーの総和をシグモイド関数に通す必要があります。

### UBJ モデル

UBJ モデルの場合、Vespa はモデルファイルから objective を読み取ります。ロジスティック objective の場合、`base_score` は自動的に変換(ロジット)されるため、手動での調整なしにモデルの出力が XGBoost の予測と一致します。


```js
schema my_app {
    rank-profile classify inherits default {
        first-phase {
            expression: xgboost("my_classifier.ubj")
        }
    }
}
```


UBJ は、最終出力へのシグモイドの適用は自動では行わないことに注意してください。ロジスティック objective で確率が必要な場合は、式を `sigmoid()` でラップしてください。


```js
schema my_app {
    rank-profile classify inherits default {
        first-phase {
            expression: sigmoid(xgboost("my_classifier.ubj"))
        }
    }
}
```


ランキング objective と `reg:squarederror` の場合は、生のツリーの総和を直接使用できます。

### JSON モデル

`dump_model()` でエクスポートされた JSON モデルの場合、objective と `base_score` は保持され**ません**。

`reg:logistic` と `binary:logistic` の場合、クラス 1 の確率を表すには、生のマージンのツリーの総和を[シグモイド関数](/ja/reference/ranking/ranking-expressions)に通す必要があります。回帰の場合、モデルは直接インポートできますが、`base_score` はダンプに含まれないため、学習時に 0 に設定すべきです。

sklearn のトイデータセットを使用した例:


```python
from sklearn import datasets
import xgboost as xgb
breast_cancer = datasets.load_breast_cancer()
c = xgb.XGBClassifier(n_estimators=20, objective="binary:logistic")
c.fit(breast_cancer.data, breast_cancer.target)
c.get_booster().dump_model("binary_breast_cancer.json", fmap="feature-map.txt", dump_format="json")
c.predict_proba(breast_cancer.data)[:, 1]
```


二値分類器に対する XGBoost の `predict_proba` 関数を Vespa で表現するには、[シグモイド関数](/ja/reference/ranking/ranking-expressions)を使用します。


```js
schema my_app {
    rank-profile prediction-binary inherits default {
        first-phase {
            expression: sigmoid(xgboost("binary_breast_cancer.json"))
        }
    }
}
```


`base_score` がデフォルト(0.5)でない場合、シグモイドだけでは不十分です。`base_score` を考慮した完全な式は次のとおりです。


```js
schema my_app {
    rank-profile prediction-binary inherits default {
        constants {
            base_score: 0.5
        }
        first-phase {
            expression: 1.0 / (1.0 + (1.0 - base_score) / base_score * exp(-(xgboost("binary_breast_cancer.json"))))
        }
    }
}
```


`0.5` を学習時に実際に使用した `base_score` に置き換えてください。完全に動作する例については、[XGBoost System Test](https://github.com/vespa-engine/system-test/tree/master/tests/search/xgboost) を参照してください。

## Vespa の推論スコアと XGBoost の predict スコアのデバッグ

* JSON モデルの場合、`base_score` と(early stopping で学習した場合の)最適なツリー数はダンプで失われます。UBJ モデルはこの情報を保持します。XGBoost には異なる predict 関数(predict/predict_proba など)もあります。次の [XGBoost System Test](https://github.com/vespa-engine/system-test/tree/master/tests/search/xgboost) は、さまざまな種類の XGBoost モデルを Vespa で表現する方法を示しています。
* 学習の際は、オフライン学習の特徴量がオンラインで Vespa が計算する特徴量と一致するように、`match-features` または `summary-features` のいずれかを使用して、特徴量を Vespa から収集すべきです。特徴量のダンプは、[recall](/ja/reference/api/query#recall) パラメーターを使用して特定のクエリーとドキュメントのペアを詳細に調べることで、差異のデバッグにも役立ちます。
* 複数のノードがモデルを使用する分散環境では、`nativeRank`、`nativeFieldMatch`、`bm25`、`fieldMatch` のようなテキストマッチング特徴量は、どのノードがヒットを生成したかによって異なる場合があります。その理由は、これらの特徴量がすべて、ローカルにインデックスされたコーパスから計算される [term(n).significance](/ja/reference/ranking/rank-features#query-features) を使用しているためです。`term(n).significance` 特徴量は、*Inverse Document Frequency (IDF)* に関連しています。各ノードはローカルのコーパスから significance の値を推定するため、グローバルな正しさを得るには、`term(n).significance` はコンテナー内の Searcher によって設定されるべきです。
