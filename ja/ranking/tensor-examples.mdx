テンソルはニューラルネットなどの機械学習モデルを表現するために使用できますが、それ以外にも多くの用途があります。Vespa のテンソルモデルは、スパースな次元、次元名、lambda 計算をサポートしているため強力です。計算したいものが何であれ、テンソル式として簡潔に表現できる可能性が高いのですが、問題はその方法を学ぶことです。このページでは、インスピレーションを提供するために、テンソル使用の実際の例をいくつか集めています。

## 現在時刻に依存する値

e コマースアプリケーションでは、指定された時間帯に異なる商品価格を設定するプロモーションがあるかもしれません。価格はランキングに使用されるため、正しい価格はランキングの中で計算されなければなりません。テンソルを使って、ドキュメント内で任意の時間帯の価格を指定し、ランキング時に正しい価格を選択することはできるでしょうか?

これを行うには、次のようにドキュメントタイプに 3 つのテンソルを追加します:

```js
field startTime type tensor(id{}} {
    indexing: attribute
}
field endTime type tensor(id{}} {
    indexing: attribute
}
field price type tensor(id{}} {
    indexing: attribute
}
```

ここで id はプロモーションの任意のラベルで、ドキュメント内で一意である必要があります。startTime と endTime はエポックタイムスタンプです。

これで、ドキュメントは次のようにプロモーションを含めることができます([ドキュメント JSON 構文](/ja/reference/schemas/document-json-format)):

```json
"startTime": { "cells": { "promo1": 40, "promo2": 60, "promo3": 80 }
"endTime": { "cells": { "promo1": 50, "promo2": 70, "promo3": 90 }
"price": { "cells": { "promo1": 16, "promo2": 18, "promo3": 10 }
```

そして、次の式で現在有効な価格を取得できます

```js
reduce((attribute(startTime) < now) * (attribute(endTime) > now) * attribute(price), max)
```

一致する時間帯がない場合は 0 を返すため、完全な式ではおそらくこれを関数でラップし、(if 式を使って)0 を返すかどうかをチェックし、そうでない場合はその商品のデフォルト価格を返すことになるでしょう。

これがなぜ正しい価格を取得するのかを理解するために、`(attribute(startTime) < now)` は次の式の[短縮形である](../reference/ranking/ranking-expressions#non-primitive-functions)ことに注目してください

```js
join(attribute(startTime), now, f(x,y)(x < y))
```

つまり、`startTime` テンソルのすべてのセルをゼロ次元の `now` テンソル(すなわち数値)で join し、now がセルのタイムスタンプより大きい場合は join されたテンソルのセル値を 1 に、そうでない場合は 0 に設定します。このテンソルを、now が小さい場所にのみ 1 を持つテンソルと乗算で join すると、結果は現在有効な時間帯を持つプロモーション id に 1 を、そうでない場合に 0 を持つテンソルになります。あとは price テンソルと乗算で join して最終的なテンソルを取得するだけです(そこから max 値を選択して非ゼロの値を取得します)。

## スカラーをテンソルに追加する

よくある状況として、密な埋め込みベクトルがあり、それに機械学習モデルへの入力としてスカラー属性(または関数の戻り値)をいくつか追加したいという場合があります。これは次の式で実現できます(密なベクトルの次元名が "x" であると仮定します):

```js
concat(concat(query(embedding),attribute(embedding),x), tensor(x[2]):[bm25(title),attribute(popularity)], x)
```

これはスカラー式の集合からテンソルを作成し、それをクエリーとドキュメントの埋め込みベクトルに連結します。

## クエリーとドキュメントのベクトル間のドット積

各ドキュメントがサイズ 4 のベクトルを含むドキュメントの集合があるとします。ドキュメントのベクトルとクエリーで渡されるベクトルとの間のドット積を計算し、そのドット積のスコアに従って結果をランク付けしたいとします。

次のスキーマファイルは、サイズ 4 の indexed 次元 `x` を 1 つ持つテンソル型の attribute テンソルフィールドを定義しています。加えて、入力とドット積計算を含む rank profile を定義します:

```js
schema example {
    document example {
        field document_vector type tensor<float>(x[4]) {
            indexing: attribute | summary
        }
    }
    rank-profile dot_product {
        inputs {
            query(query_vector) tensor<float>(x[4])
        }
        first-phase {
            expression: sum(query(query_vector)*attribute(document_vector))
        }
    }
}
```

indexed テンソルの短縮形を使用した、ベクトル [1.0, 2.0, 3.0, 5.0] を持つ [JSON](/ja/reference/schemas/document-json-format#tensor) ドキュメントの例:

```json
[
    {
        "put": "id:example:example::0",
        "fields": {
            "document_vector" : [1.0, 2.0, 3.0, 5.0]
        }
    }
]
```

ベクトル [1.0, 2.0, 3.0, 5.0] を searcher でクエリーに設定する例:

```java
public Result search(Query query, Execution execution) {
    query.getRanking().getFeatures().put("query(query_vector)",
        Tensor.Builder.of(TensorType.fromSpec("tensor<float>(x[4])")).
        cell().label("x", 0).value(1.0).
        cell().label("x", 1).value(2.0).
        cell().label("x", 2).value(3.0).
        cell().label("x", 3).value(5.0).build());
    return execution.search(query);
}
```

## クロス特徴量を用いたロジスティック回帰モデル

機械学習を利用する簡単な方法のひとつは、一連の基本特徴量からクロス特徴量を生成し、それらに対してロジスティック回帰を行うことです。これを Vespa のテンソルでどのように表現できるでしょうか?

3 つの基本特徴量があると仮定します:

```js
query(interests): tensor(interest{}) - A sparse, weighted set of the interests of a user.
query(location): tensor(location{}) - A sparse set of the location(s) of the user.
attribute(topics): tensor(topic{}) - A sparse, weighted set of the topics of a given document.
```

これらから、これらの特徴量のすべての 3 次元の組み合わせを生成し、ロジスティック回帰モデルをトレーニングして、可能な各組み合わせに対する重みを得たとします:

```js
tensor(interest{}, location{}, topic{})
```

この重みテンソルは、[constant テンソル](/ja/reference/schemas/schemas#constant)としてアプリケーション・パッケージに追加できます。これを `constant(model)` としましょう。これにより、rank profile 内で次の式によってモデルを計算できます

```js
sum(query(interests) * query(location) * attribute(topics) * constant(model))
```

ここで、最初の 3 つの因子が 3 次元のクロス特徴量テンソルを生成し、最後の因子がそれらを学習済みの重みと組み合わせます。

## 1 次元ベクトルと 2 次元行列の行列積

テンソル型 `tensor<float>(x[3],y[2])` を持つ attribute テンソルフィールド `document_matrix` で表現された 3x2 行列があり、その内容が次のとおりであると仮定します:

```json
{ {x:0,y:0}:1.0, {x:1,y:0}:3.0, {x:2,y:0}:5.0, {x:0,y:1}:7.0, {x:1,y:1}:11.0, {x:2,y:1}:13.0 }
```

また、型 `tensor<float>(x[3])` のテンソルとしてクエリーで渡される 1x3 ベクトルがあり、その内容が次のとおりであると仮定します:

```json
{ {x:0}:1.0, {x:1}:3.0, {x:2}:5.0 }
```

これは、[query feature](/ja/ranking/ranking-expressions-features#using-query-variables) で指定されているとおり、searcher で `query(query_vector)` として設定されます。

1x3 ベクトルと 3x2 行列の行列積を計算する(結果として 1x2 ベクトルを得る)には、次のランキング式を使用します:

```bash
sum(query(query_vector) * attribute(document_matrix),x)
```

これは、共有次元 `x` に対する疎テンソル積の後に、同じ次元に対する sum を行うものです。

## テンソルをルックアップ構造として使用する

マップド次元を持つテンソルはマップに似ていますが、より汎用的です。必要なのが単純なマップのルックアップだけだとしたらどうでしょうか?詳細は[テンソルのパフォーマンス](/ja/performance/feature-tuning#mapped-lookups)を参照してください。

テンソル attribute `my_map` があり、これが特定のドキュメントの値であると仮定します:

```json
tensor<float>(x{},y[3]):{a:[1,2,3],b:[4,5,6],c:[7,8,9]}
```

3 つの名前付きベクトル(a、b、c)のどれを別の計算に使用するかを選択するクエリーを作成するには、ルックアップしたいラベルをテンソルの中にラップします。次の型/値を持つクエリーテンソル `my_key` を仮定します:

```json
tensor<float>(x{}):{b:1.0}
```

ルックアップを実行すると、型 `tensor<float>(y[3])` のテンソルが返されます:

```js
sum(query(my_key)*attribute(my_map),x)
```

キーが何にも一致しない場合、結果は空になります: `tensor<float>(y[3]):[0,0,0]`。それ以外の動作にしたい場合は、事前にルックアップが成功するかどうかをチェックし、成功しない場合はフォールバック式を実行するようにします。例えば次のようにします:

```js
if(reduce(query(my_key)*attribute(my_map),count) == 3,
  reduce(query(my_key)*attribute(my_map),sum,x),
  tensor<float>(y[3]):[0.5,0.5,0.5])
```

<Note>
 **注:** 

上記は、`(y*x){x:b}` のような [slice](../reference/ranking/ranking-expressions#slice) を作成するのと同じと考えることができます。上記の構文では最適化された実行が可能です。例は [Tensor Playground](https://docs.vespa.ai/playground/#N4KABGBEBmkFxgNrgmUrWQPYAd5QFNIAaFDSPBdDTAO30gFssATAgGwGcSybIiEkAC4FanLACcAFIwD6ASxbAAvsQAeiAMwBdAJRxgjAIxxEAFgB0ABmJgArNdsA2a9tuMATKYDsjsAA4-AE5XZUheCGVeVV5qclwGIlIaKEo0CLoGZjZ2BRYeFIh+BhExSRk8lX1DLyNrMIyojBiMOMwEwSSMinw28npBRgBDHBwCFll2LCwAawBXPGTC4sFOOcYZVg5OACpsjjziOUVdcJSm1BbUPqgOwgK+NJuigahOdnkAYy7C+8FNnK7fa5E6GPJwTwNc7RFDaEDKIA)にあります。

## lambda によるスライス

一般的なユースケースとして、テンソル lambda 関数を使用して、`m` 次元(`m` は `k` より大きい)のベクトル表現から最初の `k` 次元をスライスして取り出すというものがあります。lambda 関数によるスライスは、[Matryoshka Representation Learning](https://arxiv.org/abs/2205.13147) 由来のベクトルを表現するのに最適です。

> Matryoshka Representation Learning (MRL) which encodes information at different granularities and allows a single embedding to adapt to the computational constraints of downstream tasks.

次の式は、テンソル `t` の最初の 256 次元をスライスします:

```js
tensor<float>(x[256])(t{x:(x)})
```

重要な点として、これは元のテンソルへの参照のみを行い、テンソルをより小さいテンソルにコピーすることを回避します。

以下は完全な例です。3072 次元の元のベクトル表現を保存しており、first-phase 式では元の表現の最初の 256 次元をスライスしてドット積を実行し、続いて second-phase 式ですべての次元にわたる完全な計算を行います。Vespa のフェーズド計算の利用については[フェーズドランキング](/ja/ranking/phased-ranking)を、また [customizing reusable frozen embeddings with Vespa](https://blog.vespa.ai/tailoring-frozen-embeddings-with-vespa/) も参照してください。

```js
schema example {
  document example {
    field document_vector type tensor<float>(x[3072]) {
      indexing: attribute | summary
    }
  }
  rank-profile small-256-first-phase {
    inputs {
      query(query_vector) tensor<float>(x[3072])
    }
    function slice_first_dims(t) {
      expression: l2_normalize(tensor<float>(x[256])(t{x:(x)}), x)
    }
    first-phase {
      expression: sum( slice_first_dims(query(query_vector)) * slice_first_dims(attribute(document_vector)) )
    }
    second-phase {
      expression: sum( query(query_vector) * attribute(document_vector) )
    }
  }
}
```
