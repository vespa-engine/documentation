サーチャーとプロセッサーの両方がリクエスト・データに直接アクセスできるため、多くの場合、独自のリクエスト・ハンドラーを実装する必要はありません。ただし、カスタム・リクエスト・ハンドラーが役立つケースがいくつかあります:


1.  カスタム REST API を実装する必要がある場合。
2. アプリケーションが、リクエストを特定の検索チェーンや処理チェーンにルーティングするためにどのパラメーターを使用するかを制御する必要がある場合。

## リクエスト・ハンドラーの実装

リクエストを受信すると、リクエスト・ハンドラーはその内容を消費し、処理し、レスポンスを返さなければなりません。リクエスト・ハンドラーを実装する最も便利な方法は、[ThreadedHttpRequestHandler](https://javadoc.io/doc/com.yahoo.vespa/container-disc/latest/com/yahoo/container/jdisc/ThreadedHttpRequestHandler) をサブクラス化することです。

このユーティリティー基底クラスは、同期 API とマルチスレッド実行モデルを使用します。また、ほとんどのリクエスト・ハンドラーに必要な多くの機能を実装しています:

- クエリーは自動的にアクセス・ログに書き込まれます
- レスポンスに HTTP の date ヘッダーが追加されます(ただし、独自のコードが date ヘッダーを追加した場合、それが上書きされることはありません)
- 例外とタイムアウトしたクエリーのロギング
- Error がスローされた場合の自動シャットダウン

## リクエスト・ハンドラーのデプロイ

アプリケーションにリクエスト・ハンドラーをデプロイするには、*services.xml* の [handler](/ja/reference/applications/services/container#handler) 要素を使用します:

```xml highlight={2-4}
<container id="default" version="1.0">
    <handler id="my.package.MyRequestHandler" bundle="the name in <artifactId> in your pom.xml">
        <binding>http://*/*</binding>
    </handler>
```

各パターンに対して [binding](/ja/reference/applications/services/container#binding) 要素を追加することで、リクエスト・ハンドラーを 0 個以上の URI パターンにバインドできます。
