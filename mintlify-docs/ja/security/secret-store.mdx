---
title: "シークレットストア"
---

Vespa Cloud は、アプリケーションで使用するシークレットの安全な保存と管理をサポートしています。シークレットとは、API キー、トークン、その他アプリケーションが必要とする非公開の構成値など、テキストベースの値です。

シークレットをボールトに整理し、アプリケーション固有のアクセス制御を設定し、シークレットをアプリケーション・コードにきれいに統合することで、Vespa Cloud は API キーやトークンなどの機密データを安全に保ち、容易に更新できるようにします。

このガイドでは、テナントのシークレット管理と、アプリケーションでのシークレットの使用方法を説明します。

シークレットストアを使い始める実践的な例としては、[Retrieval Augmented Generation (RAG) in Vespa](https://github.com/vespa-engine/sample-apps/tree/master/retrieval-augmented-generation#deploying-to-the-vespa-cloud-using-gpu) サンプル・アプリケーションを使用してください。この例では、シークレットストアを使用して OpenAI API キーを保存しています。

## シークレット管理

Vespa Cloud コンソールでは、テナントの「Account」セクションに「Secret store」タブがあります。ここでテナントのすべてのシークレットを構成します。

### ボールト

シークレットはボールトに整理され、各ボールトには複数のシークレットを含めることができます。ボールトには、ボールト内のシークレットをどのアプリケーションが使用できるかというルールも含まれます。ボールトはいくつでも持つことができます。

新しいボールトを作成するには、「+ New vault」ボタンをクリックします。ボールト名はルール `[.a-zA-Z0-9_-]` に一致する必要があります。つまり、英数字と `.`、`_`、`-` のみが許可されます。スペースは使用できません。

<Frame>![シークレットストアの概要](/assets/img/secret-store.png)</Frame>

作成後、右上の赤いゴミ箱ボタンをクリックすると、ボールト全体を削除できます。

### アクセス制御

各ボールトには「Access control」セクションがあり、ボールト内のシークレットにどのアプリケーションがアクセスできるかを決定します。アプリケーションごとに、どの環境（[dev](/ja/operations/environments#dev) または [prod](/ja/operations/environments#prod)（test と staging を含む））内でアプリケーションがアクセスできるかを設定できます。

アクセス制御を設定するには、事前にアプリケーションが作成されている必要があることに注意してください。アプリケーションを作成してアクセスを許可するには、[Retrieval Augmented Generation (RAG) in Vespa](https://github.com/vespa-engine/sample-apps/tree/master/retrieval-augmented-generation#deploying-to-the-vespa-cloud-using-gpu) の手順を使用してください。

### シークレット

新しいシークレットを追加するには、「+ New secret」ボタンをクリックします。シークレットにも同じ命名規則が適用されます。シークレットには任意の値を設定できます。一度保存すると、シークレットは二度と表示されないことに注意してください。シークレットを新しい値に更新することはできますが、実際の値を取得することはできません。シークレットの最大長は 64K 文字です。

各テナントには 15 個のシークレットという上限があります。

<Frame>![新しいシークレットの作成](/assets/img/secret-store-secret.png)</Frame>

シークレットの作成後は、シークレットを新しい値に更新したり、削除したりできます。

シークレットが更新されると、それを使用しているアプリケーションは 60 秒以内にこの新しい値を使い始めることに注意してください。

また、アプリケーションが何らかの理由で利用できないシークレット（定義されていない、またはアクセス権がない）を要求した場合、アプリケーションのデプロイは成功しないことにも注意してください。

## 例: RAG に OpenAI API キーを使用する

OpenAI API キーをシークレットとして使用する RAG 検索チェーンを設定します:

```xml expandable
<services version="1.0" xmlns:deploy="vespa" xmlns:preprocess="properties">
    <container id="default" version="1.0">

        {/* configure the OpenAI API key secret */}
        <secrets>
            <apiKey vault="my-vault" name="openai-api-key" />
        </secrets>

        {/* configure the OpenAI client to use the secret */}
        <component id="openai" class="ai.vespa.llm.clients.OpenAI">
            <config name="ai.vespa.llm.clients.llm-client">
                <apiKeySecretRef>apiKey</apiKeySecretRef>
            </config>
        </component>

        {/* configure a search chain to use the OpenAI client */}
        <search>
            <chain id="rag" inherits="vespa">
                <searcher id="ai.vespa.search.llm.RAGSearcher">
                    <config name="ai.vespa.search.llm.llm-searcher">
                        <providerId>openai</providerId>
                    </config>
                </searcher>
            </chain>
        </search>

    </container>
</services>
```

実践的な例については、[Retrieval Augmented Generation (RAG) in Vespa](https://github.com/vespa-engine/sample-apps/tree/master/retrieval-augmented-generation#deploying-to-the-vespa-cloud-using-gpu) を試してください。

## シークレットの使用

アプリケーションでシークレットを使用するには、`services.xml` に `secrets` を追加します:

```xml
<services version="1.0" xmlns:deploy="vespa" xmlns:preprocess="properties">
    <container id="default" version="1.0">

        <secrets>
            <myApiKey vault="my-vault" name="my-api-key" />
        </secrets>

    </container>
</services>
```

この例では、ボールト `my-vault` 内の `my-api-key` という名前のシークレットを、アプリケーション内では `myApiKey` という名前で参照しています。

カスタム・コンポーネントでこのシークレットにアクセスするには、Searcher などのコンポーネントのコンストラクター・パラメーターとして `Secrets` を注入します:

```java expandable
import ai.vespa.secret.Secret;
import ai.vespa.secret.Secrets;
...

public class MySearcher extends Searcher {

    private final Secret apiKeySecret;

    public MySearcher(Secrets secrets) {
        apiKeySecret = secrets.get("myApiKey");
    }

    @Override
    public Result search(Query query, Execution execution) {
        String apiKey = apiKeySecret.current();
        // ... do something with the current value of secret ...
        return execution.search(query);
    }

}
```

通常は、クラスに `Secret` を保持し、シークレットの値自体を使用したいときに `Secret.current();` を呼び出します。これにより、シークレットが更新された場合でも、現在のシークレット値を使用できます。コンテナー・コードで現在のシークレット値が更新されるまで、最大 60 秒かかることがあることに注意してください。

`current` の値自体を保持しないようにしてください。そうしてしまうと、構成が変更されてもシークレット値が更新されません。
