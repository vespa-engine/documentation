## 空のフィールド

一般的に、フィード時に値を受け取らなかったフィールドは、ドキュメントのレンダリング時に無視されます。これらは空のフィールドと見なされます。ただし、特定のフィールド型には、空と見なされる値がいくつか存在します。例えば、空文字列("")は空と見なされ、空の配列([])も同様です。各型の詳細については上記の表を参照してください。

## ドキュメント操作

詳細は[読み取りと書き込み](/ja/writing/reads-and-writes)を参照してください - 選択肢:

- [Vespa CLI](/ja/clients/vespa-cli#documents)を使用します。
- [/document/v1/](/ja/reference/api/document-v1): このAPIはリクエストごとに1つの操作を受け付け、ドキュメントIDはURLにエンコードされます。 
- [Vespa feed client](/ja/clients/vespa-feed-client): HTTP経由でドキュメント操作を非同期にVespaへフィードするJava API / コマンドラインツールです。 

### Put

"put"のペイロードには"put"操作と、フィールド値を含む["fields"](#field-types)があります([/document/v1/ の例](/ja/writing/document-v1-api-guide#post)):

```json
{
    "put": "id:mynamespace:music::123",
    "fields": {
        "title": "Best of Bob Dylan"
    }
}
```

### Get

"get"にはペイロードがありません - レスポンスには"put"と同じ"field"オブジェクトに加えて、"id"と"pathId"フィールドが含まれます([/document/v1/ の例](/ja/writing/document-v1-api-guide#get)):

```json
{
    "pathId": "/document/v1/mynamespace/music/docid/123",
    "id": "id:mynamespace:music::123",
    "fields": {
        "title": "Best of Bob Dylan"
    }
}
```

### Remove

"remove"のペイロードには"remove"操作のみがあります([/document/v1/ の例](/ja/writing/document-v1-api-guide#delete)):

```json
{
    "remove": "id:mynamespace:music::123"
}
```

### Update

"update"のペイロードには"update"操作と"fields"があります。注意: 各フィールドには、フィールド値を直接指定するのではなく、[更新操作](#update-operations)を含める必要があります([/document/v1/ の例](/ja/writing/document-v1-api-guide#put)):

```json
{
    "update": "id:mynamespace:music::123",
    "fields": {
        "title": {
            "assign": "The best of Bob Dylan"
        }
    }
}
```

フラグを追加することで、[test and set](#test-and-set)条件を付加したり、更新時に新しいドキュメントを[作成](#create)できるようにしたり(いわゆる「upsert」操作)できます。

#### Test and set

操作にオプションの _condition_ を追加して、_test and set_ 条件を指定できます - [条件付き書き込み](/ja/writing/document-v1-api-guide#conditional-writes)を参照してください。_condition_ の値は文字列としてエンコードされた[ドキュメント・セレクション](/ja/reference/writing/document-selector-language)です。例: _sales_ フィールドが既に999と等しい場合にのみインクリメントします([/document/v1/ の例](/ja/writing/document-v1-api-guide#conditional-writes)):

```json
{
    "update": "id:mynamespace:music::bob/BestOf",
    "condition": "music.sales==999",
    "fields": {
        "sales": {
            "increment": 1
        }
    }
}
```

<Info>
 **注:** 条件には _fieldname_ だけでなく、_documenttype.fieldname_ を使用してください。
</Info>

条件が満たされない場合、412レスポンスコードが返されます。

#### create(存在しない場合に作成)

存在しないドキュメントに対する**更新**は、_create_ を使用してサポートされます([/document/v1/ の例](/ja/writing/document-v1-api-guide#create-if-nonexistent)):

```json
{
    "update": "id:mynamespace:music::bob/BestOf",
    "create": true,
    "fields": {
        "title": {
            "assign": "The best of Bob Dylan"
        }
    }
}
```

Vespa 8.178以降、_create_ は条件付き**Put**操作と組み合わせて使用することもできます([/document/v1/ の例](/ja/writing/document-v1-api-guide#conditional-updates-and-puts-with-create) - 使用前にそこにある注意事項を確認してください):

```json
{
    "put": "id:mynamespace:music::123",
    "condition": "music.sales==999",
    "create": true,
    "fields": {
        "title": "Best of Bob Dylan"
    }
}
```

## 更新操作

更新操作は次のとおりです: [`assign`](#assign)、[`add`](#add)、[`remove`](#composite-remove)、[算術演算](#arithmetic)(`increment` `decrement` `multiply` `divide`)、[`match`](#match)、[`modify`](#tensor-modify)

## assign

`assign` は、フィールド(またはコレクションの要素)の値を新しい値で置き換えるために使用します。assignの際は、一般に `put` 操作でそのフィールドの値をフィードするときと同じ構文と構造を使用できます。

### 単一値フィールド

```js
field title type string {
    indexing: summary
}
```

```json
{
    "update": "id:mynamespace:music::example",
    "fields": {
        "title": {
            "assign": "The best of Bob Dylan"
        }
    }
}
```

### テンソル・フィールド

```js
field tensorfield type tensor(x{},y{}) {
    indexing: attribute | summary
}
```

```json 
{
    "update": "id:mynamespace:tensordoctype::example",
    "fields": {
        "tensorfield": {
            "assign": {
                "cells": [
                    { "address": { "x": "a", "y": "b" }, "value": 2.0 },
                    { "address": { "x": "c", "y": "d" }, "value": 3.0 }
                ]
            }
        }
    }
}
```

これにより、このフィールドに格納されているテンソル全体が完全に置き換えられます。

### structフィールド

#### struct内のすべてのフィールドを置き換える

structのキー/値ペアのオブジェクトをassignすることで、struct全体が置き換えられます。

```js
struct person {
    field first_name type string {}
    field last_name type string {}
}
field contact type person {
    indexing: summary
}
```

```json
{
    "update": "id:mynamespace:workers::example",
    "fields": {
        "contact": {
            "assign": {
                "first_name": "Bob",
                "last_name": "The Plumber"
            }
        }
    }
}
```

#### 個別のstructフィールド

個別のstructフィールドは[フィールドパス](#fieldpath)構文を使用して更新します。structを使用する際の制約については[リファレンス](/ja/reference/schemas/schemas#struct-name)を参照してください。

```json
{
    "update": "id:mynamespace:workers::example",
    "fields": {
        "contact.first_name": {
            "assign": "Bob"
        },
        "contact.last_name": {
            "assign": "The Plumber"
        }
    }
}
```

### マップ・フィールド

個別のマップ・エントリーは[フィールドパス](/ja/reference/schemas/document-field-path)構文を使用して更新できます。次の宣言では、`key` がIntegerで、値が `person` structである `map` を定義しています。

```js
struct person {
    field first_name type string {}
    field last_name type string {}
}
field contact type map<int, person> {
    indexing: summary
}
```

`contact` マップのエントリーの一部を更新する例:

- `contact` は更新対象のマップ・フィールドの名前です
- `{0}` は更新されるキーです
- `first_name` は `person` struct内で更新されるstructフィールドです

```json
{
    "update": "id:mynamespace:workers::example",
    "fields": {
        "contact{0}.first_name": {
            "assign": "John"
        }
    }
}
```

マップのキーに要素をassignすると、そのキー/値のマッピングが存在しない場合は挿入され、既に存在する場合は新しい値で上書きされます。マップを使用する際の制約については[リファレンス](/ja/reference/schemas/schemas#map)を参照してください。

#### プリミティブ値へのマップ

```js
field my_food_scores type map<string, string> {
    indexing: summary
}
```

```json
{
    "update": "id:mynamespace:food::example",
    "fields": {
        "my_food_scores{Strawberries}": {
            "assign": "Delicious!"
        }
    }
}
```

#### structへのマップ

```js
struct contact_info {
    field phone_number type string {}
    field email type string {}
}
field contacts type map<string, contact_info> {
    indexing: summary
}
```

```json
{
    "update": "id:mynamespace:people::d_duck",
    "fields": {
        "contacts{\"Uncle Scrooge\"}": {
            "assign": {
                "phone_number": "555-123-4567",
                "email": "number_one_dime_luvr1877@example.com"
            }
        }
    }
}
```

### 配列フィールド

#### プリミティブ値の配列

```js
field ingredients type array<string> {
    indexing: summary
}
```

配列全体をassignする:

```json
{
    "update": "id:mynamespace:cakes:tasty_chocolate_cake",
    "fields": {
        "ingredients": {
            "assign": ["sugar", "butter", "vanilla", "flour"]
        }
    }
}
```

配列内の既存要素にassignする:

```json
{
    "update": "id:mynamespace:cakes:tasty_chocolate_cake",
    "fields": {
        "ingredients[3]": {
            "assign": "2 cups of flour (editor's update: NOT asbestos!)"
        }
    }
}
```

インデックス要素3が存在している必要があることに注意してください。matchを使用した別の方法:

```json
{
    "update": "id:mynamespace:cakes:tasty_chocolate_cake",
    "fields": {
        "ingredients": {
            "match": {
                "element": 3,
                "assign": "2 cups of flour (editor's update: NOT asbestos!)"
            }
        }
    }
}
```

個別の配列要素は、[フィールドパス](/ja/reference/schemas/document-field-path)または[match](#match)構文を使用して更新できます。

#### structの配列

[structの配列](/ja/reference/schemas/schemas#array)を使用する際の制約についてはリファレンスを参照してください。

```js
struct person {
    field first_name type string {}
    field last_name type string {}
}
field people type array<person> {
    indexing: summary
}
```

```json
{
    "update": "id:mynamespace:students:example",
    "fields": {
        "people[34]": {
            "assign": {
                "first_name": "Bobby",
                "last_name": "Tables"
            }
        }
    }
}
```

要素のインデックスが存在している必要があることに注意してください。新しい要素を追加するには[add](#add-array-elements)を使用してください。matchを使用した別の構文:

```json
{
    "update": "id:mynamespace:students:example",
    "fields": {
        "people": {
            "match": {
                "element": 34,
                "assign": {
                     "first_name": "Bobby",
                     "last_name": "Tables"
                }
            }
        }
    }
}
```


### weighted setフィールド

weighted setに新しい要素を追加するには、[add](#add-weighted-set)を使用するか、`field{key}` 構文でassignします。後者の例:

```js
field int_weighted_set type weightedset<int> {
    indexing: summary
}
field string_weighted_set type weightedset<string> {
    indexing: summary
}
```

```json
{
    "update":"id:mynamespace:weightedsetdoctype::example1",
    "fields": {
        "int_weighted_set{123}": {
            "assign": 123
        },
        "int_weighted_set{456}": {
            "assign": 100
        },
        "string_weighted_set{\"item 1\"}": {
            "assign": 144
        },
        "string_weighted_set{\"item 2\"}": {
            "assign": 7
        }
    }
}
```

weighted setに対して `field{key}` 構文を使用すると、[add](#add-weighted-set)を使用する場合よりも効率が落ちる _可能性がある_ ことに注意してください。

### フィールドのクリア

フィールドをクリアするには、`null` 値をassignします。

```json
{
    "update": "id:mynamespace:music::example",
    "fields": {
        "title": {
            "assign": null
        }
    }
}
```

## add

`add` は、配列、weighted set、またはテンソルのマップ次元にエントリーを追加するために使用します。

### 配列要素の追加

追加されたエントリーは、指定された順序で配列の末尾に追加されます。

```js
field tracks type array<string> {
    indexing: summary
}
```

```json
{
    "update": "id:mynamespace:music::https://music.yahoo.com/bobdylan/BestOf",
    "fields": {
       "tracks": {
            "add": [
                "Lay Lady Lay",
                "Every Grain of Sand"
            ]
        }
    }
}
```

### weighted setエントリーの追加

weighted setの要素を追加するには、JSONのキー/値構文を使用します。値は要素のウェイトです。

既に存在するキー/ウェイトのマッピングを追加すると、既存のウェイトが新しいもので上書きされます。

```js
field int_weighted_set type weightedset<int> {
    indexing: summary
}
field string_weighted_set type weightedset<string> {
    indexing: summary
}
```

```json
{
    "update":"id:mynamespace:weightedsetdoctype::example1",
    "fields": {
        "int_weighted_set": {
            "add": {
                "123": 123,
                "456": 100
            }
        },
        "string_weighted_set": {
            "add": {
                "item 1": 144,
                "item 2": 7
            }
        }
    }
}
```

### テンソル・セルの追加

マップ(mapped)または混合(mixed)テンソルにセルを追加します。インデックス次元のみを持つテンソルには無効です。既に存在するセルを追加すると、セルの値が新しい値で上書きされます。アドレスは完全に指定する必要がありますが、束縛されたインデックス次元が指定されていないセルにはデフォルト値 `0.0` が設定されます。その他の例については、システムテスト[tensor add update](https://github.com/vespa-engine/system-test/tree/master/tests/search/tensor_feed/tensor_add_remove_update)を参照してください。

```js
field tensorfield type tensor(x{},y[3]) {
    indexing: attribute | summary
}
```

```json
{
    "update": "id:mynamespace:tensordoctype::example",
    "fields": {
        "tensorfield": {
            "add": {
                "cells": [
                    { "address": { "x": "b", "y": "0" }, "value": 2.0 },
                    { "address": { "x": "b", "y": "1" }, "value": 3.0 }
                ]
            }
        }
    }
}
```

この例では、セル `{"x":"b","y":"2"}` は暗黙的に0.0に設定されます。

つまり、次のテンソルから始めた場合:

```json
{
    {"x": "a", "y": "0"}: 0.2,
    {"x": "a", "y": "1"}: 0.3,
    {"x": "a", "y": "2"}: 0.5,
}
```

上記のadd操作を適用すると、次のテンソルになります:

```json
{
    {"x": "a", "y": "0"}: 0.2,
    {"x": "a", "y": "1"}: 0.3,
    {"x": "a", "y": "2"}: 0.5,
    {"x": "b", "y": "0"}: 2.0,
    {"x": "b", "y": "1"}: 3.0,
    {"x": "b", "y": "2"}: 0.0,
}
```

混合テンソルには、代わりに _ブロック短縮形_ を推奨します。これにより、インデックス次元を持つセルが指定されないという問題も回避できます:

```json
{
    "update": "id:mynamespace:tensordoctype::example",
    "fields": {
        "tensorfield": {
            "add": {
                "blocks": [
                    { "address": { "x": "b" }, "values": [2.0, 3.0, 5.0] }
                ]
            }
        }
    }
}
```

## remove

`remove` を使用して、配列、weighted set、マップ、テンソルから要素を削除します。

### 配列フィールド

配列フィールドは、"remove" と削除する値の配列を使用した、値による削除をサポートしています。

例えば、次のフィールドがあるとします:

```js
field string_array type array<string> {
    indexing: summary
}
```

この更新は、"hello" または "1" であるすべての配列要素を削除します:

```json
{
    "update":"id:mynamespace:weightedsetdoctype::example1",
    "fields": {
        "string_array": {
            "remove": ["hello", 1]
        }
    }
}
```

### weighted setフィールド

```js
field string_weighted_set type weightedset<string> {
    indexing: summary
}
```

```json
{
    "update":"id:mynamespace:weightedsetdoctype::example1",
    "fields": {
        "string_weighted_set": {
            "remove": {
                "item 2": 0
            }
        }
    }
}
```

### マップ・フィールド

```
field string_map type map<string, string> {
    indexing: summary
}
```

```json
{
    "update":"id:mynamespace:mapdoctype::example1",
    "fields": {
        "string_map{item 2}": {
            "remove": 0
        }
    }
}
```

### テンソル・フィールド

マップ(mapped)または混合(mixed)テンソルからセルを削除します。インデックス次元のみを持つテンソルには無効です。マップ次元とインデックス次元の両方を持つテンソルでは、マップ次元のみを指定してください。マップ次元が指すすべてのインデックス・セルは暗黙的に削除されます。その他の例については、システムテスト[tensor remove update](https://github.com/vespa-engine/system-test/tree/master/tests/search/tensor_feed/tensor_add_remove_update)を参照してください。

```js
field tensorfield type tensor(x{},y[2]) {
    indexing: attribute | summary
}
```

```json
{
    "update": "id:mynamespace:tensordoctype::example",
    "fields": {
        "tensorfield": {
            "remove": {
                "addresses": [
                    {"x": "b"},
                    {"x": "c"}
                ]
            }
        }
    }
}
```

この例では、セル `{x:b,y:0},{x:b,y:1},{x:c,y:0},{x:c,y:1}` が削除されます。

アドレスにマップ次元のサブセットのみを指定することもサポートされています。その場合、指定された次元のラベル値に一致するすべてのセルが削除されます。次の例では、次元 `x` のラベルが `b` であるすべてのセルが削除されます。

```js
field tensorfield type tensor(x{},y{},z[2]) {
    indexing: attribute | summary
}
```

```json
{
    "update": "id:mynamespace:tensordoctype::example",
    "fields": {
        "tensorfield": {
            "remove": {
                "addresses": [
                    {"x": "b"}
                ]
            }
        }
    }
}
```

## 算術演算

4つの算術演算子 `increment`、`decrement`、`multiply`、`divide` は、更新を適用する前に現在の値を参照することなく、_単一値_ の数値を変更するために使用します。例:

```js
field sales type int {
    indexing: summary | attribute
}
```

```json
{
    "update": "id:mynamespace:music::https://music.yahoo.com/bobdylan/BestOf",
    "fields": {
        "sales": {
            "increment": 1
        }
    }
}
```

## match

_weighted setまたは配列_ の特定のキーに対して算術演算を行う場合は、`match` 操作を使用します:

```js
field track_popularity type weightedset<string> {
    indexing: summary | attribute
}
```

```json
{
    "update": "id:mynamespace:music::https://music.yahoo.com/bobdylan/BestOf",
    "fields": {
        "track_popularity": {
            "match": {
                "element": "Lay Lady Lay",
                "increment": 1
            }
        }
    }
}
```

つまり、weighted set "track\_popularity" に対して、要素 "Lay Lady Lay" を `match` し、そのウェイトを1だけ `increment` します。存在しないキーのインクリメントでキーの自動作成をトリガーする方法については、[weightedset properties](/ja/reference/schemas/schemas#weightedset-properties)リファレンスを参照してください。

更新対象のフィールドが配列の場合、`element` の値は正の整数になります。

<Info>
 **注:** 1回の操作でマッチできる要素は1つだけです。
</Info>

## テンソルの変更

テンソル内の個別のセルは、`modify` 更新を使用して変更できます。セルは指定された操作に従って変更されます:

- `replace` - 単一のセル値を置き換えます
- `add` - 既存のセル値に値を加算します
- `multiply` - 既存のセル値に値を乗算します

セルのアドレスは完全に指定する必要があります。セルが存在しない場合、そのセルへの更新は無視されます。modify更新を適用する前に存在しないセルを作成するには、`"create": true`(下記の例を参照)を使用します。その他の例については、システムテスト[tensor modify update](https://github.com/vespa-engine/system-test/tree/master/tests/search/tensor_feed/tensor_modify_update)を参照してください。

```js
field tensorfield type tensor(x[3]) {
    indexing: attribute | summary
}
```

```json
{
    "update": "id:mynamespace:tensordoctype::example",
    "fields": {
        "tensorfield": {
            "modify": {
                "operation": "replace",
                "addresses": [
                    { "address": { "x": "1" }, "value": 7.0 },
                    { "address": { "x": "2" }, "value": 8.0 }
                ]
            }
        }
    }
}
```

この例では、セル `{"x":"1"}` は値7.0に、`{"x":"2"}` は値8.0に置き換えられます。代わりに操作 `add` または `multiply` を使用した場合、7.0と8.0はセル `{"x":"1"}` と `{"x":"2"}` の現在の値に加算または乗算されます。

単一のマップ次元を持つテンソルでは、_セル短縮形_ も使用できます:

```js
field tensorfield type tensor(x{}) {
    indexing: attribute | summary
}
```

```json
{
    "update": "id:mynamespace:tensordoctype::example",
    "fields": {
        "tensorfield": {
            "modify": {
                "operation": "add",
                "create": true,
                "cells": {
                    "b": 5.0,
                    "c": 6.0
                }
            }
        }
    }
}
```

この例では、セル `{"x":"b"}` に5.0が、セル `{"x":"c"}` に6.0が加算されます。`"create": true` を指定すると、modify更新を適用する前に、入力テンソルに存在しないセルが作成されます。デフォルトのセル値は、`replace` と `add` では0.0、`multiply` では1.0です。つまり、存在しないセルは操作で指定された値になります。

混合テンソルでは、_ブロック短縮形_ を使用して密なサブスペース全体を変更することもできます:

```js
field tensorfield type tensor(x{},y[3]) {
    indexing: attribute | summary
}
```

```json
{
    "update": "id:mynamespace:tensordoctype::example",
    "fields": {
        "tensorfield": {
            "modify": {
                "operation": "replace",
                "blocks": {
                    "a": [1,2,3],
                    "b": [4,5,6]
                }
            }
        }
    }
}
```

## フィールドパス

フィールドパス(Fieldpath)は、複合構造内のフィールドにアクセスするためのものです。インデックスやattributeの一部ではない構造については、フィールドパスを使用して要素に直接アクセスできます。これは、フィールド値に追加情報を加えることで行います。マップ構造の場合は、キーを指定します([例](#assign)を参照)。

```js
mymap{mykey}
```

そして、"mykey" をキーとする要素に対して操作を行います。配列にもアクセスできます([詳細](#assign)を参照)。

```js
myarray[3]
```

これはstructにも当てはまります([詳細](#assign)を参照)。**注:** structの更新は[index](/ja/reference/applications/services/content#document)モードでは機能しません:

```json
mystruct.value1
```

これはネストされた構造でも機能します。例えば、`struct` の `array` への `map` の `map`:

```json
{
    "update": "id:mynamespace:complexdoctype::foo",
    "fields": {
        "nested_structure{firstMapKey}{secondMapKey}[4].title": {
            "assign": "Look at me, mom! I'm hiding deep in a nested type!"
        }
    }
}
```
