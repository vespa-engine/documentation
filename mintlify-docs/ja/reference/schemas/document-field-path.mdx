---
title: "ドキュメント・フィールド・パスのリファレンス"
---

フィールド・パス構文は、配列、構造体(struct)、マップ、セットを通じてドキュメントをたどり、式に一致する値の集合を生成するために、Vespa のいくつかの場所で使用されます。例 - ドキュメントにフィールド `mymap` が含まれ、それがキー `mykey` を持つ場合、この式はそのキーに対するマップの値を返します:

```bash
mymap{mykey}
```

`myarray` フィールドのインデックス 3 の値が設定されていれば、それを返します:

```bash
myarray[3]
```

構造体フィールド `mystruct` 内の `value1` フィールドの値が設定されていれば、それを返します:

```bash
mystruct.value1
```

mystructarray が構造体を含む配列フィールドの場合、それらの各構造体の value1 の値を返します:

```bash
mystructarray.value1
```

各フィールド・タイプには次の構文を使用でき、必要に応じて再帰的に組み合わせることができます:

<Info>
マップ、Weighted Set、配列の添字の値を指定する際には、数値と文字列のみが使用できることに注意してください。
</Info>

## 変数

<Warning>
 **非推奨:** 非推奨です。Vespa 9 で削除されます。
</Warning>

共通の変数を使用して複数のフィールド・パスを参照できると便利な場合があります。たとえば、構造体の配列がある場合、同じ配列インデックス内のフィールドに対してドキュメント・セレクションをまとめて使用したいことがあります。これは次のような式で実現できます:

```bash
mydoctype.mystructarray{$x}.field1=="foo" AND mydoctype.mystructarray{$x}.field2=="bar"
```

変数は、`key` 値(マップおよび Weighted Set の場合)または `index` 値(配列の場合)のいずれかを持ちます。変数はこれらのコンテキストをまたいで使用することはできません(つまり、マップのキーを配列のインデックスとして使用することはできません)。
