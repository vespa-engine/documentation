追加のファイルやディレクトリは、アプリケーション・パッケージ内の任意の場所に配置できます。これらはアプリケーション・パッケージのデプロイ時に Vespa によって明示的に処理されることはありません(つまり、アプリケーション・パッケージ内から参照されている場合にのみ考慮されます)が、将来のリリースでどのように処理されるかについての保証はありません。将来のすべてのリリースで Vespa に無視されることが保証された形でアプリケーション・パッケージを拡張するには、*ext/* ディレクトリを使用してください。

アプリケーション・パッケージはデプロイのために zip 化できます:

```bash
$ zip -r ../app.zip .
```

zip ファイルには任意の名前を使用できます。[deploy](/ja/clients/vespa-cli#deployment) コマンドでは、パスの代わりにそのファイルを指定してください。

<Warning>
**重要:** 

`tar` / `gzip` の使用はサポートされていません。[詳細](https://github.com/vespa-engine/vespa/issues/17837)。
</Warning>

## プリプロセス・ディレクティブ

プリプロセス・ディレクティブは以下の用途で使用します:

- *preprocess:properties*: *services.xml* 内のどこからでも参照できるプロパティを定義します
- *preprocess:include*: *services.xml* を小さなチャンクに分割します

以下では、*`${container.port}`* は *4099* に置き換えられます。*content.xml* の内容は *include* の位置に配置されます。これは再帰的に適用され、名前空間がトップレベルのファイルで定義されている限り、インクルードされたファイル内でもプリプロセス・ディレクティブを使用できます:

```xml
<services version="1.0" xmlns:preprocess="properties">
    <preprocess:properties>
        <container.port>4099</container.port>
    </preprocess:properties>
    <container version="1.0">
        <http>
            <server id="container" port="${container.port}" />
        </http>
        <search />
    </container>
    <preprocess:include file="content.xml" />
</services>
```

*content.xml* のサンプル:

```xml
<content version="1.0" >
    <redundancy>1</redundancy>
    <documents>
        <document type="music.sd" mode="index" />
    </documents>
    <nodes>
        <node hostalias="node0"/>
        <node hostalias="node1"/>
        <node hostalias="node2"/>
    </nodes>
</content>
```

## アプリケーション・パッケージのバージョニング

アプリケーションにはユーザー定義のバージョンを与えることができ、[/ApplicationStatus](/ja/applications/components#monitoring-the-active-application) で確認できます。バージョンは [services.xml](/ja/reference/applications/services/services) の(トップレベルで)設定します:

```xml
<services>
    <config name="container.handler.observability.application-userdata">
        <version>42</version>
    </config>
    ...
</services>
```
