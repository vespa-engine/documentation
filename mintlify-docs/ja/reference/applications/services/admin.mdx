[services.xml](/ja/reference/applications/services/services) の `<admin>` のリファレンス・ドキュメントです。この設定の動作する例は、サンプル・アプリケーション *multinode-HA* の [services.xml](https://github.com/vespa-engine/sample-apps/blob/master/examples/operations/multinode-HA/services.xml) にあります。

```yaml
admin [version]
    adminserver [hostalias]
    cluster-controllers
        cluster-controller [hostalias, baseport, jvm-options, jvm-gc-options]
    configservers
        configserver [hostalias, baseport]
    logserver [jvm-options, jvm-gc-options]
    slobroks
        slobrok [hostalias, baseport]
    monitoring [systemname]
    metrics
        consumer [id]
            metric-set [id]
            metric [id]
            cloudwatch [region, namespace]
                shared-credentials [file, profile]
    logging
```

## adminserver

設定されたノードは、Vespa システムにおけるデフォルトの管理ノードになります。つまり、別途設定しない限り、すべての管理サービス(ログサーバー、コンフィグレーション・サーバー、slobrok など)がこのノードで実行されます。これらのサービスのいずれかに baseport や jvm オプションを指定する必要がある場合は、[configservers](#configservers)、[logserver](#logserver)、[slobroks](#slobroks) 要素を使用してください。

1 つ以上の [cluster-controller](#cluster-controller) 要素のコンテナーです。1 つ以上の [content](/ja/reference/applications/services/content) クラスターがある場合、少なくとも 1 つのクラスター・コントローラーの設定が必要です。

## logging

Java プラグインのログレベルのチューニングに使用します。あるクラスやパッケージからのデバッグ・ロギングを(一時的に)有効にする必要がある場合や、サードパーティのコンポーネントが不要な INFO レベルのメッセージでログを埋め尽くしている場合に、レベルのオン/オフを切り替えられます。例:

```xml
<logging>
    <class name="org.myorg.MyHelperClass" levels="+debug" />
    <class name="org.thirdparty.TooSpammyClass" levels="-info" />
    <package name="org.myorg.tricky.package" levels="all" />
    <package name="org.anotherorg" levels="all -info -debug -spam" />
</logging>
```

チューニングはサブパッケージにも影響するため、上記の設定は `org.anotherorg.` をプレフィックスとするすべてのパッケージにも影響することに注意してください。また、`org.myorg.tricky.package.foo.InternalClass` が存在する場合、そこからは「spam」レベルのロギングまで出力されます!

`levels` のデフォルトは `"all -debug -spam"` で、上記のように特定のレベルを追加・削除できます。

## metrics

グラフ表示アプリケーションへのメトリクスの転送を設定するために使用します。`consumer` 子要素を追加してください。[監視](/ja/operations/self-managed/monitoring)も参照してください。例:

```xml
<metrics>
    <consumer id="my-metric-namespace">
        <metric-set id="default" />
        <metric id="my-custom-metric" />
        <cloudwatch region="us-east-1" namespace="my-vespa">
            <shared-credentials file="/path/to/credentials-file" profile="default" />
        </cloudwatch>
    </consumer>
</metrics>
```

## consumer

メトリクス・コンシューマーを設定します。この要素に含まれるメトリクスは、指定した id のコンシューマーにエクスポートされます。`consumer` は [/metrics/v1/values](/ja/reference/api/metrics-v1)、[/metrics/v2/values](/ja/reference/api/metrics-v2)、[/prometheus/v1/values](/ja/reference/api/prometheus-v1) のリクエスト・パラメーターです。

`metric` および/または `metric-set` 子要素を追加してください。

## metric

  <thead>

    </tr>
  </tbody>

メトリック id には、*.average* などのメトリック固有のサフィックスを含める必要があることに注意してください。

この例では、デフォルトのメトリック・セットに加えて、カスタム・コンシューマーに 1 つのメトリックが追加されています。prometheus エンドポイントには *&consumer=my-custom-consumer* パラメーターを使用してください。.count サフィックスにも注目してください。[プロセス・メトリクス API](/ja/reference/api/state-v1#state-v1-metrics) を参照してください。

プロセスごとのメトリクス API エンドポイント */state/v1/metrics* には、出力される各メトリックの説明も含まれます。*/state/v1/metrics* エンドポイントには、メトリックの集計値(.count、.average、.rate、.max)も含まれます。

```xml
<metrics>
    <consumer id="my-custom-consumer">
        <metric-set id="default" />
        <metric id="vds.idealstate.garbage_collection.documents_removed.count" />
    </consumer>
</metrics>
```
