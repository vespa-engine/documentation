これはコンテナー設定の *search* 部分のリファレンスです。関連: [チェーン化されたコンポーネント](/ja/applications/chaining)および[フェデレーションのチュートリアル](/ja/querying/federation)。検索設定のルート要素は、[container](/ja/reference/applications/services/container) のサブ要素として宣言します:

```yaml
search
    binding
    searcher [id, class, bundle, provides, before, after]
    federation [id]
        source [idref]
            federationoptions [timeout, requestTimeout, optional]
        source-set [inherits]
        target-selector
    chain [id, inherits, excludes]
        searcher [id, class, bundle, provides, before, after]
        federation [id]
            source [idref]
                federationoptions [timeout, requestTimeout, optional]
            source-set [inherits]
            target-selector
    provider [id, type, cluster, excludes]
        federationoptions [timeout, requestTimeout, optional]
        source [id]
            searcher [id, class, bundle, provides, before, after]
    renderer [id, class, bundle]
    significance
    threadpool
        threads [ max ]
        queue
```

[config](/ja/reference/applications/config-files#generic-configuration-in-services-xml) は、個々の検索チェーンや searcher によってオーバーライドされない限り、JDisc クラスターの検索チェーン内のすべての searcher に適用されます。

## binding

SearchHandler をマップする URI です。デフォルトのバインディングは `http://*/search/*` です。複数の要素を指定できます。例:

```xml
<binding>http://*/search/*</binding>
```

## searcher

searcher 要素は、[chain](#chain) 要素の中、または search ルートに含まれます。

searcher 要素は、*定義*(*id* を使用)または*参照*(*idref* を使用)のいずれかです。

searcher の定義により、ちょうど 1 つの searcher インスタンスが生成されます。このインスタンスは searcher 要素の内容に従ってセットアップされます。検索チェーン要素の中に含まれる searcher 定義は、*インナー searcher* を定義します。それ以外の場合は、*アウター searcher* を定義します。

## federation

federation は [searcher](/ja/applications/searchers#searchers) の一種です(上記参照)。この要素は*フェデレーション*を実装します。つまり、各クエリーを一連の検索チェーンに並列に送信し、その結果を結合する searcher インスタンスを定義します。フェデレーションおよびその子要素である [source](#source)、[source-set](#source-set)、[target-selector](#target-selector)、そして [provider](#provider) の使い方や例については、[フェデレーションガイド](/ja/querying/federation)を参照してください。

```xml
<federation id="componentId">
    <source idref="componentSpecification" />
    <target-selector />
</federation>
```

## target-selector

フェデレーション先の検索チェーンを選択するために使用するコンポーネントを指定します。このコンポーネントは com.yahoo.search.federation.selection.TargetSelector を継承していなければなりません。属性とサブ要素については [component](/ja/reference/applications/services/container#component) を参照してください。

## source-set

たとえば組み込みの federation searcher のソースを複製するために使用します:

```xml
<federation id="combinator">
    <source-set inherits="default" />
    …
</federation>
```

## source

それを囲む federation searcher が使用するソースへの参照です。子要素の [federationoptions](#federationoptions) は省略可能です。

```xml
<source idref="componentSpecification">
    <federationoptions/>
</source>
```

## federationoptions

[source](#source) または [provider](#provider) に含まれます。federation searcher が特定の検索チェーンに*どのように*フェデレーションするかを指定します。フェデレーションオプション A が別のフェデレーションオプション B を*オーバーライド*する場合、結果は次の内容を含む新しいフェデレーションオプションになります:

- A に存在しない B のすべてのオプション
- A のすべてのオプション

ソースまたはプロバイダーにフェデレーションする際、federation searcher はデフォルトでは検索チェーンのフェデレーションオプションを使用します。[source 参照](#source-reference)にフェデレーションオプションが含まれている場合、それを囲む federation searcher から使用されるときには、検索チェーンのオプションをオーバーライドします。

## significance

[searcher](#searcher) に含まれます。1 つ以上のグローバルな significance [モデル](#model)を指定します。

```xml
<significance>
    <model model-id="significance-en-wikipedia-v1"/>
    <model url="https://some/uri/my-model.model.multilingual.json"/>
    <model path="models/my-model.no.json.zst"/>
</significance>
```

モデルは *Vespa* によって提供されるか、[vespa-significance ツール](/ja/reference/operations/self-managed/tools#vespa-significance)で生成します。順序がモデルの優先度を決定し、最後の要素が最も高い優先度を持ちます。これらのモデルを使用するには、スキーマで [rank-profile 内の significance モデルを有効化](/ja/reference/schemas/schemas#significance)する必要があります。

サブ要素:

- [model](#model)(必須、1 つ以上)

## model

[significance](#significance) に含まれます。[グローバル significance モデル](/ja/ranking/significance#global-significance-model)を指定します。モデルは `model-id` によって、またはアプリケーション・パッケージ内のモデルファイルへの `url` もしくは `path` を指定することによって識別されます。

`model-id` を持つモデルは *Vespa* によって提供されており、[こちら](/ja/rag/model-hub#significance-models)に一覧があります。`model-id` を使用した例:

```xml
<model model-id="significance-en-wikipedia-v1"/>
```

`url` および `path` で指定されるモデルは JSON ファイルであり、[zstandard](https://facebook.github.io/zstd/) で圧縮することもできます。モデルファイルは [vespa-significance ツール](/ja/reference/operations/self-managed/tools#vespa-significance)を使用して生成できます。`url` を使用した例:

```xml
<model url="https://some/uri/mymodel.multilingual.json"/>
```

`path` を持つモデルは、アプリケーション・パッケージ内に配置する必要があります。パスはアプリケーション・パッケージのルートからの相対パスです。`path` を使用した例:

```xml
<model path="models/mymodel.no.json.zst"/>
```

## chain

検索チェーンをどのようにインスタンス化するか、および含まれる searcher をどのように順序付けるかを指定します。属性と子要素については[チェーンのリファレンス](/ja/reference/applications/services/processing#chain)を参照してください。チェーンは他のチェーンから searcher を[継承](/ja/reference/applications/services/processing#inherits)でき、順序付けに[フェーズ](/ja/reference/applications/services/processing#phase)を使用できます。なお、[provider](#provider) 要素と [source](#source) 要素もチェーンです。クエリー内で検索チェーンを指定するには [searchChain](/ja/reference/api/query#searchchain) を使用します。

searcher がコンテント・クラスターにクエリーをディスパッチできるように、組み込みの *vespa* チェーンを継承する例:

```xml
<chain id="common" inherits="vespa">
    <searcher class="com.yahoo.vespatest.ExtraHitSearcher" id="CommonSearcher" bundle="the name in <artifactId> in your pom.xml" >
        <config name="vespatest.extra-hit">
            <exampleString>A searcher for ...</exampleString>
        </config>
    </searcher>
</chain>
```

省略可能なサブ要素:

- searcher または federation(1 つ以上)。参照または定義のいずれかです。searcher に指定した名前が*アウター searcher* と一致する場合、それは *searcher 参照*です。それ以外の場合は *searcher 定義*です。searcher 定義である場合、それは同時に「*まさに*この searcher を使用する」という暗黙的な searcher 参照でもあります。これらの searcher 要素はすべて異なる名前を持たなければなりません。
- [phase](/ja/reference/applications/services/processing#phase)(1 つ以上)。
- [config](/ja/reference/applications/config-files#generic-configuration-in-services-xml)(1 つ以上。この検索チェーン内のすべての*インナー* searcher に適用されます。ただし、個々のインナー searcher によってオーバーライドされる場合を除きます)。

[include](/ja/reference/applications/services/container#include) を使用して、アプリケーション・パッケージ配下のディレクトリ内の個別ファイルに検索設定を置くことができます。各ファイルには上記のような `<search>` 要素を 1 つ含める必要があります。Vespa は、そこに設定された各チェーンがあたかも `services.xml` に「インライン」で書かれているかのように動作します。これは、複数の開発者がそれぞれの検索チェーンを、たとえば別々のパッケージでデプロイする必要がある場合に便利です。

<Note>
**注:** 

複数のコンテナー・クラスターを使用している場合、モジュール化された検索チェーンはすべてのクラスターで利用可能になります。
</Note>

各 searcher 参照は、searcher 定義の*タイプ*と一致していなければなりません。たとえば、searcher 参照 *federation idref="myId"* は、*searcher id="myId"* ではなく、*federation id="myId"* として定義されたアウター searcher と一致する必要があります。

## source

ソース検索チェーンと、それに関連付けられたソースを定義します。

```xml
<provider id="providerA">
    <source id="commonSource">
        <searcher id="com.yahoo.example.AddHitSearcher" bundle="the name in <artifactId> in your pom.xml" >
            <config name="vespatest.hit-title">
                <hitTitle>providerA</hitTitle>
            </config>
        </searcher>
    </source>
</provider>
```

指定されたコンポーネント id は、関連付けられたソースの id です。関連付けられたソースは、同じソース名を持つすべてのソース検索チェーンで構成されます。

"id" 属性を使用してソース名を指定できるのは、単一のソース検索チェーンだけです。この検索チェーンは*リーダー*と呼ばれます。それ以外のソース検索チェーンは、"idref" 属性を使用してソース名を指定しなければなりません。後者の検索チェーンはパーティシパントと呼ばれます。

ソースは*フェデレーション*に使用できます。ソースにフェデレーションする場合、通常はリーダー検索チェーンが使用されます。パーティシパント検索チェーンのいずれかを使用するには、次のクエリーパラメーターを設定する必要があります: source.*sourceId*.provider.*providerId*。

ソース検索チェーンの id は *sourceId@providerId* です。この検索チェーンは、それを囲む provider を自動的に継承します。また、それを囲む provider のフェデレーションオプションも自動的に継承します。ソースにフェデレーションオプションが含まれている場合、継承したものをオーバーライドします。それ以外のすべての点において、この検索チェーンは他の検索チェーンと同様に動作します。

## threadpool

jdisc search handler のスレッドプールの設定を指定します。すべてのパラメーターは CPU コア数に対する相対値です。[コンテナー・チューニングの例](/ja/performance/container-tuning#container-worker-threads-example)を参照してください。このスレッドプールは省略可能な `max` 属性もサポートしており、負荷がかかるとプールは最大 `max * vCPU` スレッドまで拡張し、5 秒間アイドル状態が続くと元に戻ります。許可されたスレッド数に達し、すべてがビジーで、かつキューが満杯になると、リクエストは拒否されます。

省略可能なサブ要素:

- [threads](#threadpool-threads)
- [queue](#threadpool-queue)
