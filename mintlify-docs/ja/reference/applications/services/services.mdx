## `<nodes>`

*nodes* 要素はクラスターのハードウェア・リソースを設定するため、コンテナー・クラスターとコンテント・クラスターの両方で使用されます。このタグは、Vespa Cloudとセルフマネージド・インスタンスで動作が異なります:

- Vespa Cloud: ノード数は *count* 属性で指定し、各ノードのリソースは [resource](#resources) 子要素で指定します。
- セルフマネージド: *nodes* はノードごとに [node](#node) 子要素を持ちます。*services.xml* で参照されるノードは、*hostalias* を使って [hosts.xml](/ja/reference/applications/hosts) で定義されている必要があります。

両方を指定して、アプリケーション・パッケージを両方の環境で機能するようにすることも可能です。また、開発のためにどちらのタイプをもう一方の環境にデプロイすることも常に可能です: nodesタグにVespa Cloud向けの内容がある場合、セルフホスト環境では単一ノードのクラスターとして解釈され、その逆も同様です。

*groups* も *group-size* も設定されていない場合、すべてのノードは単一のグループに属します。詳細は[トポロジー](/ja/performance/topology-and-resizing)をお読みください。

## `<resources>`

Vespa Cloudの [nodes](#nodes) 配下: クラスター内の各ノードが持つべきリソースを指定します。

リソースは、デプロイ先に応じて、[AWS](/ja/performance/instance-types/aws-instance-types)、[GCP](/ja/performance/instance-types/gcp-instance-types)、[Azure](/ja/performance/instance-types/azure-instance-types) のノード・フレーバーと一致する必要があります。例外: リモート・ディスクを使用する場合は、最大サイズより小さい任意の数を指定できます。

## `<gpu>`

Vespa Cloudの [resources](#resources) 配下: プロビジョニングするGPUリソースを宣言します。

制限事項:

- AWSゾーンでのみ利用可能
- コンテナー・クラスターでのみ有効

<table className="vespa-table">
  <thead>
    <tr>
      <th>属性</th>
      <th>型</th>
      <th>説明</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>&#42;&#42;count&#42;&#42;</td>
      <td>整数</td>
      <td>GPUの数</td>
    </tr>
    <tr>
      <td>&#42;&#42;memory&#42;&#42;</td>
      <td>整数。"Gb" などのバイト単位を後ろに付ける</td>
      <td>GPUあたりのメモリ量。利用可能なGPUメモリの総量は、この数値に <code>{`count`}</code> を掛けたものです。</td>
    </tr>
  </tbody>
</table>

例:

```xml
<nodes count="2">
    <resources vcpu="4" memory="16Gb" disk="125Gb">
        <gpu count="1" memory="16Gb"/>
    </resources>
</nodes>
```

## ゾーン固有の設定

次のような設定を表現するには、*デプロイメント・バリアント* を使用します:

```xml
<nodes deploy:environment="prod"
       deploy:region="aws-use1-az4"
       count="20">
    <resources vcpu="4" memory="16Gb" disk="125Gb"/>
</nodes>
```

詳細とその他のオプションについては、[デプロイメント・バリアント](/ja/operations/deployment-variants)を参照してください。

## `<config>` を使った汎用設定

*services.xml* のほとんどの要素は、*config* という名前のサブ要素を受け付けます。*config* 要素はXML構造のさまざまなレベルに含めることができ、下位レベルのものが上位レベルの値をオーバーライドします(以下に例)。*config* 要素には *name* 属性を含める必要があり、これは名前空間を含む、対象の設定オプションの完全な名前を与えます。この名前は、Vespaに同梱されている設定定義、または[アプリケーション・パッケージ](../config-files.html)の一部である設定定義のどちらも参照できます。汎用設定の完全な例については、[アプリケーション・パッケージ](/ja/reference/applications/config-files#generic-configuration-in-services-xml)のリファレンスを参照してください。

```xml
<container id="default" version="1.0">
    <handler id="com.yahoo.vespatest.ConfiguredHandler">
        <config name="vespatest.response">
            <response>configured string</response>
        </config>
    </handler>
</container>
```

## モジュラー設定

一部の機能は、アプリケーション・パッケージのサブディレクトリにあるXMLファイルを使って設定できます。これは、これらのXMLファイルにある設定が、*services.xml* にインライン記述されたかのように使用されることを意味します。これは [search chain](/ja/reference/applications/services/search#chain)、[docproc chain](/ja/reference/applications/services/docproc)、[ルーティング・テーブル](/ja/writing/document-routing#routing-services)でサポートされています。
