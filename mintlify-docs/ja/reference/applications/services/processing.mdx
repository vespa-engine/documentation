title: "services.xml - processing"

このドキュメントでは、`services.xml` の [`container`](/ja/reference/applications/services/container) 部分のサブ要素である `processing` の構文とセマンティクスについて説明します。`processing` は、検索やクエリー処理に特に依存しない、純粋な[リクエスト・レスポンス処理](/ja/applications/processing)アプリケーションを設定するためのものです。processing ブロックは[プロセッサー](/ja/applications/processing)の設定に使用します:

```yaml expandable
processing
    binding
    processor [id, class, bundle, provides, before, after]
        provides
        before
        after
    renderer [id, class, bundle]
    chain [id, inherits, excludes]
        processor [idref, id, class, bundle, provides, before, after]
            provides
            before
            after
        inherits
            chain
            exclude
        phase [id, before, after]
            before
            after
```

例:

```xml
<processing>
    <processor id="processor1" class="com.yahoo.test.Processor1" />
    <chain id="default">
        <processor idref="processor1"/>
        <processor id="processor2" class="com.yahoo.test.Processor2"/>
    </chain>
    <renderer id="renderer1" class="com.yahoo.test.Renderer1" />
</processing>
```

## binding

ProcessingHandler をマップする URI です。デフォルトのバインディングは `http://*/processing/*` です。複数の要素を指定できます。例:

```xml
<binding>http://*/processing/*</binding>
```

## provides

フェーズや他のプロセッサーが依存関係として利用できるように、プロセッサーが提供する名前です。例:

```xml
<provides>IntentAnalysis</provides>
```

## chain

[プロセッサー](/ja/reference/applications/services/processing)、[サーチャー](/ja/reference/applications/services/search)、[ドキュメント・プロセッサー](/ja/reference/applications/services/docproc)(つまりコンポーネント)のチェーンを定義するための要素です。チェーンとは、依存関係によって順序付けられた集合です。依存関係はフェーズを通じて表現され、フェーズは他のフェーズやコンポーネントに依存できます。ネットワークからの受信リクエストに対しては、*default* という名前のチェーンが呼び出されます。ガイドとして[チェーン化されたコンポーネント](/ja/applications/chaining)を参照してください。*id* または *idref* のいずれかが必須です。

Searcher、Document processing、Processing の各チェーンは、再起動なしで実行時に変更できます。変更には、チェーン内のプロセッサーの追加/削除や、チェーンおよびプロセッサーの名前の変更が含まれます。変更を行い、[デプロイ](/ja/basics/applications#deploying-applications)してください。一部の変更にはコンテナーの再起動が必要です。[ドキュメント処理の再設定](/ja/applications/document-processors#reconfiguring-document-processing)を参照してください。

## inherits

1 つ以上の親チェーンから継承します。

検索チェーンが別の検索チェーンを継承すると、親チェーンからフェーズと*サーチャー参照*(暗黙的に定義されたものと明示的に定義されたものの両方)を取り込みます。

継承した 2 つ以上のコンポーネント参照が同じ名前を持つ場合、それらに一致する新しいコンポーネント指定が代わりに使用されます。それが不可能な場合(つまり、バージョン指定を統合できない場合や、異なるチェーンのコンポーネント定義が必要になる場合)はエラーが通知されます。

コンポーネント参照は、結果として得られるチェーン・インスタンスでどのインスタンスが使用されるかを決定します。

コンポーネント参照とは、「このチェーンには指定した名前のコンポーネントがちょうど 1 つ存在し、そのコンポーネントはバージョン指定に一致しなければならない」ということを表すコンポーネント指定です。

コンポーネント参照は、同じ名前を持つ継承されたコンポーネント参照を*オーバーライド*します(つまり、継承されたものは無視されます)。

指定したコンポーネント参照に複数のコンポーネントが一致する場合は、(バージョンで判断して)最も新しいものが使用されます。

## exclude

継承したチェーンからコンポーネントを除外します。

## phase

省略可能なサブ要素:

- before: 属性と同じ
- after: 属性と同じ

以下は等価です:

```xml
<phase id="name">
    <before>phaseName1</before>
    <after>phaseName2</after>
</phase>

<phase id="name" before="phaseName1" after="phaseName2" />
```

例:

```xml
<chain id="demo">
    <phase id="CheckpointName">
        <before>IntentAnalysis</before>
        <after>OtherAnalysis</after>
    </phase>
    <processor id="processor2" class="com.yahoo.test.Processor2"/>
</chain>
```

## before

このフェーズまたはコンポーネントの後に実行されるべきフェーズまたはコンポーネントの名前です。複数の `before` 要素を使用して、チェーン内でこのコンポーネントまたはフェーズの後に常に実行されるべき複数のコンポーネントやフェーズを定義できます。言い換えると、定義されたフェーズまたはコンポーネントは、要素内の名前より*前*に配置されます。

## after

このフェーズまたはコンポーネントの前に実行されるべきフェーズまたはコンポーネントの名前です。複数の `after` 要素を使用して、チェーン内でこのコンポーネントまたはフェーズの前に常に実行されるべき複数のコンポーネントやフェーズを定義できます。言い換えると、定義されたフェーズまたはコンポーネントは、要素内の名前より*後*に配置されます。
