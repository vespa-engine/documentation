これは、[services.xml](/ja/reference/applications/services/services)におけるコンテナー・クラスター設定のリファレンスです。

```yaml expandable

    http
        server [id, port]
        filtering
    handler [id, class, bundle]
        binding
        component
    server [id, class, bundle]
    clients
        client [id, permissions]
            certificate [file]
            token [id]
    components
    component
    search
        include [dir]
        binding
        searcher
        federation
        provider
        chain
        renderer
        threadpool
        significance
    document-processing
        include [dir]
        documentprocessor
        chain
        threadpool
    processing
        include [dir]
        binding
        processor
        chain
        renderer
    document-api
        abortondocumenterror
        retryenabled
        route
        maxpendingdocs
        maxpendingbytes
        retrydelay
        timeout
        tracelevel
        mbusport
        ignore-undefined-fields
        max-document-size
    model-evaluation
        onnx
    inference
        memory
    document [type, class, bundle]
    accesslog [type, fileNamePattern, symlinkName, rotationInterval, rotationScheme]
        request-content [samples-per-second, path-prefix, max-bytes]

    nodes [count, allocated-memory, jvm-gc-options, jvm-options]
```

## handler

`handler` 要素は、リクエストハンドラーの設定を保持します。各 `binding` タグに対して、ハンドラーは指定されたバインディングを使用して該当するJDiscインターフェースにバインドされます。

- `binding` JDiscリクエストハンドラーの場合、このサーバー・バインディングをこのハンドラーに追加します。
- [`component`](#component) 別のコンポーネントを注入するために使用します。参照ではなく、新しいコンポーネントの宣言でなければなりません。

```xml
    <handler bundle="the name in <artifactId> in pom.xml" id="com.mydomain.vespatest.ExampleHandler"/>
    <nodes>
        <node hostalias="node1"/>
    </nodes>
</container>
```

## clients

Vespa Cloud専用。`clients` 要素は、[client](#client)セキュリティ設定の親要素です。詳細と実践的な例は[セキュリティ・ガイド](/ja/security/guide#configuring-tokens)を参照してください。例:

```xml
<container id="query" version="1.0">
    <clients>
        <client id="mtls" permissions="read">
            <certificate file="security/clients.pem"/>
        </client>
        <client id="query-token-client" permissions="read">
            <token id="query-token"/>
        </client>
    </clients>
</container>
```

```xml
<container id="default" version="1.0">
```

```xml
              bundle="the name in <artifactId> in pom.xml"
              type="vehicle"/>
    <document class="com.mydomain.concretedocs.Vehicle"
              bundle="the name in <artifactId> in pom.xml"
              type="ship"/>
    <document class="com.mydomain.concretedocs2.Disease"
              bundle="the name in <artifactId> in pom.xml"
              type="disease"/>
    <search/>
    <document-processing>
        <chain id="default">
            <documentprocessor bundle="the name in <artifactId> in pom.xml"
                               id="concretedocs.ConcreteDocDocProc"/>
        </chain>
    </document-processing>
    ...
</container>
```

## threadpool

`Vespa 8.611.13` 以降で利用可能です。

コンテナーのデフォルトのスレッドプールの設定を指定します。すべてのパラメーターはCPUコア数に対する相対値です - [コンテナー・チューニングの例](/ja/performance/container-tuning#container-worker-threads-example)を参照してください。このスレッドプールはオプションの `max` 属性もサポートしており、負荷がかかるとプールを最大 `max * vCPU` スレッドまで拡張し、5秒間アイドル状態が続くと縮小します。許可されたスレッド数に達し、すべてがビジーで、キューが満杯になると、リクエストは拒否されます。

### threads

vCPUコア数に対する永続スレッド数の相対値です。デフォルト値は `2` です。
