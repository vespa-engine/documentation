このノートでは、Vespa メジャーバージョン 6 と 7 の間の変更点を記載します。[Vespa のバージョン](/ja/learn/releases#versions)に記載されているとおり、メジャーバージョンは互換性の破壊を示すために使用されるものであり、重要な新機能のリリースのためではありません(新機能はマイナーバージョンでリリースされます)。ただし、メジャーバージョンにおいても、互換性が破壊されるのは 2 つの特定の方法に限られます。**デフォルトの変更**とは、以前の動作を維持するためにアプリケーションで一部のオプションを明示的に設定する必要がある可能性があることを意味し、**非推奨機能の削除**とは、*以前に非推奨とされた機能を使用しているアプリケーション*が動作し続けるために変更を必要とすることを意味します。

ほとんどの非推奨機能は、コンパイル時(Java API の非推奨)またはデプロイ時(アプリケーション・パッケージの非推奨)に警告を発生させます。ただし、Web サービス API については非推奨警告を出す方法がないため、ドキュメント内で非推奨としてマークすることに頼らざるを得ません。

このことから、アプリケーションの所有者は Vespa 7 との互換性を保つために次の 3 つのタスクを行う必要があります:

- [デフォルトの変更](#changed-defaults)によってアプリケーションで追加の設定が必要になるかどうかを確認します(トークナイゼーションとステミングの変更により、6 から 7 への変更では**その可能性が高い**ことに注意してください)。
- Vespa 6 でのコンパイルおよびデプロイ時に非推奨警告が出ていないことを確認します。
- 削除された Web サービス API および API パラメーターのリストを確認し、アプリケーションのクライアントがこれらを使用していないことを確認します。

Vespa 7 は新機能を導入しないため、その直前の Vespa 6 の各バージョンと同程度に安全かつ成熟しています。Vespa 7 のリリース以降、いかなる理由でも Vespa 6 のリリースは行われません。

### JDK バージョン

Vespa bundle-plugin が OSGi バンドルに対して正しいインポートパッケージのセットを生成するためには、Java コンポーネントを JDK 11 で再ビルドする必要があります。

### 削除された Java API

Vespa 6 で非推奨としてマークされていたクラスとメソッドは削除されました。アプリケーションのビルド時に Vespa API の非推奨警告が出る場合は、Vespa 7 に移行する前に修正しなければなりません。

### コンテナーのランタイム環境

次の maven アーティファクトはランタイムで提供されなくなりました:

- commons-codec:commons-codec
- org.apache.httpcomponents:httpclient
- org.apache.httpcomponents:httpcore

これらの依存関係のいずれかが必要な場合は、pom.xml でスコープ 'compile' として追加し、バンドルに組み込む必要があります。

### デフォルト JSON 結果フォーマットの変更

デフォルトの JSON クエリー結果フォーマットにおける **position** 型フィールドの内容は、Vespa 6 では XML としてレンダリングされていましたが、JSON としてレンダリングされるようになりました。

具体的には、position フィールドの内容は次のような文字列としてレンダリングされていました

`  <position x="-121996000" y="37401000" latlong="N37.401000;W121.996000"/>  `

しかし現在は、代わりに JSON マップとしてレンダリングされます:

```json
{
  "y": 37401000,
  "x": -121996000,
  "latlong": "N37.401000;W121.996000"
}
```

### その他の変更
