## コンテントノードのサマリーキャッシュ

サマリーキャッシュはサマリーリクエストをキャッシュするもので、[proton チューニング設定](/ja/reference/applications/services/content#summary)によって有効化されます。proton のサマリーキャッシュを有効にする場合は、以下のように proton がサマリーデータを読み込む方式も mmap から directio に変更する必要があります。サマリーキャッシュにより、チャンク化されたサマリーデータのブロック(デフォルト 64 KB)の展開に費やされる IO と CPU を節約できます。

サマリーキャッシュは複数のドキュメントタイプ間で共有される点に注意してください。

デフォルトではキャッシュは有効で、利用可能なメモリの最大 5% を使用します。設定例:

```xml
<content id="music" version="1.0">
  <engine>
    <proton>
      <tuning>
        <searchnode>
          <summary>
            <io>
              <read>directio</read>
            </io>
            <store>
              <cache>
                <maxsize-percent>5</maxsize-percent><!--percentage of available memory on the content node-->
              </cache>
            </store>
          </summary>
        </searchnode>
      </tuning>
    </proton>
  </engine>

</content>
```

<Note>
**注:** 

リクエストされた document-summary が[属性](/ja/content/attributes)であるフィールドのみを含む場合、サマリーストア(およびキャッシュ)は使用されません。
</Note>

## プロトコルフェーズのキャッシュ

[クエリー API リファレンス](/ja/reference/api/query)で説明されている *ranking.queryCache* と *groupingSessionCache* は、あるクエリーのフェーズ間でのみデータをキャッシュするため、他のクエリーには効果がありませんが、これらのキャッシュは*特定の*クエリーにおけるコンテナーとコンテントノード間のラウンドトリップを節約します。
