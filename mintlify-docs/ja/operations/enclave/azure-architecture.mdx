### アーキテクチャー

Vespa Cloud Enclave では、Vespa Cloud アプリケーションに関連するすべての Azure リソースは、共有の Vespa Cloud サブスクリプションではなく、お客様の Enclave 用 Azure サブスクリプション内に配置されます。

各 Vespa Cloud [ゾーン](/ja/operations/zones)には、Enclave サブスクリプション内に対応するゾーン・リソース・グループ(RG)があり、そのゾーンのすべてのリソースを含みます。たとえば、1 つの Virtual Network(VNet、いわゆる [VPC](https://cloud.google.com/vpc/))を持ちます。

#### 仮想マシン、ロード・バランサー、Blob Storage

Vespa Cloud サブスクリプション内の Configuration Server は、デプロイされている Vespa アプリケーションに基づいて、仮想マシン(図中の「Vespa Hosts」)の作成または破棄を決定します。Configuration Server はまた、デプロイされた Vespa アプリケーションとの通信に必要な Container Load Balancer もセットアップします。

各 Vespa Host は、ゾーン RG 内の Storage Account にある Blob Storage コンテナー(「Log Archive」)へ定期的にログを同期します。この Storage Account は Enclave に対して「ローカル」であり、お客様の Azure サブスクリプション内で Terraform モジュールによってプロビジョニングされます。

#### ネットワーキング

ゾーンの Virtual Network(VNet、いわゆる VPC)はネットワーク的に厳しく制限されています。Vespa Host はパブリック IPv4 アドレスを持ちません。ただし、アプリケーションは [NAT ゲートウェイ](https://learn.microsoft.com/en-us/azure/nat-gateway/nat-overview)を使用して外部の IPv4 サービスに接続できます。Vespa Host はパブリック IPv6 アドレスを持ち、アウトバウンド接続を行うことができます。インバウンド接続は許可されません。アウトバウンド IPv6 接続は、Configuration Server との通信のブートストラップと、運用メトリクスを Vespa Cloud に報告するために使用されます。

Vespa Host が起動すると、Configuration Server への暗号化トンネルをセットアップします。セットアップ後、Configuration Server と Vespa Host の間のすべての通信はこのトンネル上で行われます。

### セキュリティー

Vespa Cloud の運用チームは、お客様のサブスクリプション内のリソースへの直接アクセス権を*持ちません*。可能なアクセスは、Vespa 自体を稼働させるために必要な管理 API を通じたもののみです。たとえばインシデントのデバッグなどで必要になった場合、直接アクセスはお客様自身によってのみ Vespa チームに付与できます。直接アクセスを有効にするには、Enclave モジュールで `enable_ssh` 入力を true に設定します。詳細は [Enclave モジュールの入力](https://registry.terraform.io/modules/vespa-cloud/enclave/azure/latest/?tab=inputs)のドキュメントを参照してください。

Enclave と Vespa Cloud Configuration Server の間のすべての通信は、証明書に埋め込まれた識別情報を用いた [mTLS](https://en.wikipedia.org/wiki/Mutual_authentication#mTLS) によって暗号化・認証・認可されます。mTLS 通信は [Athenz](https://www.athenz.io/) サービスによって実現されています。

保存されるすべてのデータは、[Encryption At Host](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview) を使用して保存時に暗号化されます。すべての鍵は Azure プラットフォームによって自動的に管理されます。

お客様の Azure サブスクリプション内にプロビジョニングされるリソースは、お客様が適用する Vespa Cloud Enclave Terraform モジュールによって、あるいは Vespa Cloud ゾーン内のオーケストレーション・サービスによってプロビジョニングされます。

リソースは、Terraform モジュールで定義された [`id-provisioner`](https://github.com/vespa-cloud/terraform-azure-enclave/blob/main/provisioner.tf) ユーザー割り当てマネージド ID を使用して、Vespa Cloud Configuration Server によってプロビジョニングされます。

お客様の Enclave を対象にアプリケーションをデプロイできるのは、(この Azure サブスクリプションを登録した)お客様の Vespa テナントのみです。

Vespa Cloud のセキュリティーに関するより一般的な情報は、[ホワイトペーパー](/ja/security/whitepaper)を参照してください。
