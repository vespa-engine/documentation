<Frame>![Vespa の概要](/assets/img/vespa-overview.svg)</Frame>

ハイライト:

- Vespa のインデックス構造は、高レートのフィールド更新のために構築されています。書き込みパフォーマンスについては[フィードのサイジングガイド](/ja/performance/sizing-feeding)、特に部分更新については[部分更新](/ja/writing/partial-updates)を参照してください。
- Vespa は非正規化データのための[親子関係](/ja/schemas/parent-child)をサポートしています。これは、1 回の書き込みですべての子ドキュメントが更新されるため、アプリケーションデータを更新するコードを簡素化するのに使用できます。
- アプリケーションはカスタムのフィード[ドキュメント・プロセッサー](/ja/applications/document-processors)や複数のコンテナー・クラスターを追加できます — 詳細は[インデックス作成](/ja/writing/indexing)を参照してください。
- Vespa の書き込みは、安定したクラスターでは*一貫性*がありますが、競合が発生した場合、Vespa は一貫性よりも可用性を優先します。[エラスティシティ](/ja/content/elasticity#consistency)のドキュメントと [Vespa の一貫性モデル](/ja/content/consistency)を参照してください。可能な場合は、特定のドキュメントの更新には同じクライアントインスタンスを使用することを推奨します — データの一貫性のためだけでなく、[パフォーマンス](/ja/performance/sizing-feeding#concurrent-mutations)のためでもあります(*concurrent mutations* を参照)。書き込み操作の[順序付け](/ja/content/content-nodes#ordering)について詳しく読んでください。パフォーマンスのためには、同じドキュメントへのフィールド更新を[1 つの更新操作](/ja/performance/sizing-feeding#client-roundtrips)にまとめてください。
- アプリケーションは[ドキュメントを自動的に期限切れにする](/ja/schemas/documents#document-expiry)ことができます。この機能は、すでに期限切れになっているドキュメントへの PUT もブロックします — [インデックス作成](/ja/writing/document-routing#document-selection)と[ドキュメント・セレクション](/ja/reference/applications/services/content#documents)を参照してください。これはタイムスタンプ付きのテストデータをフィードする際によくある問題で、書き込みが警告なく破棄されます。

[トラブルシューティング](/ja/operations/self-managed/admin-procedures#troubleshooting)も参照してください。

高度なツール / デバッグツール:

- [vespa-feed-client](/ja/clients/vespa-feed-client): [/document/v1/](/ja/reference/api/document-v1) を使用してドキュメント操作をフィードするための Java ライブラリおよびコマンドラインクライアント。
- [vespa-feeder](/ja/reference/operations/self-managed/tools#vespa-feeder) は [Message Bus](/ja/writing/document-routing) 経由でフィードするためのユーティリティです。
- [vespa-get](/ja/reference/operations/self-managed/tools#vespa-get) は [Message Bus](/ja/writing/document-routing) 経由で単一のドキュメントを取得します。
- [vespa-visit](/ja/reference/operations/self-managed/tools#vespa-visit) は [Message Bus](/ja/writing/document-routing) 経由で複数のドキュメントを取得します。

## フィードフロー

[Vespa CLI](/ja/clients/vespa-cli)、[vespa-feed-client](/ja/clients/vespa-feed-client)、[pyvespa python クライアント](https://vespa-engine.github.io/pyvespa/reads-writes)、または [/document/v1/ API](/ja/reference/api/document-v1) を使用してドキュメントの読み書きを行います:

<Frame>![フィードクライアントによるフィード](/assets/img/elastic-feed-container.svg)</Frame>

あるいは、[vespa-feeder](/ja/reference/operations/self-managed/tools#vespa-feeder) を使用してファイルをフィードするか、[Java Document API](/ja/writing/document-api-guide) を使用します。

<Frame>![vespafeeder によるフィード](/assets/img/elastic-feed-vespafeeder.svg)</Frame>

[インデックス作成](/ja/writing/document-routing#routing-for-indexing)および / または[ドキュメント処理](/ja/applications/document-processors)は、ドキュメントが保存される前にドキュメントを操作するプロセッサーのチェーンです。ドキュメント・プロセッサーはユーザー定義が可能です。インデックス検索を使用する場合、チェーンの最終ステップでドキュメントのインデックス作成の準備が行われます。

[Document API](/ja/writing/document-api-guide) はリクエストをコンテントノード上のディストリビューターに転送します。詳細については、[コンテントノード](/ja/content/content-nodes)と[検索コア](/ja/content/proton)を参照してください。
