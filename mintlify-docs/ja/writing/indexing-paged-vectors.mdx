---
title: "ページド・ベクトルのインデックス"
---

ベクトル(テンソル)インデックスのデータの大部分は、ベクトルそのものです。インデックスへのクエリー時にも、ベクトルをインデックスに追加する時にも、真の距離を計算するためにベクトル・データへのアクセスが必要であり、高次元性のため、これらのアクセスは実質的にランダムになります。ある程度高いレイテンシーが許容できるのであれば、インデックスされたベクトル属性をディスクに[ページング](/ja/content/attributes/#paged-attributes)して*クエリー*に使うことは可能ですが、それでは大規模なベクトル・インデックスを妥当な速度で構築することはできません。高品質なインデックスを作成するには、各ベクトルの挿入時に多数の距離計算を行う必要があり、インデックス内のベクトルが RAM に載っていない場合、書き込みスループットが低下します。

利用可能なメモリーより大きなベクトル・インデックスを効率的に構築するには、ここで説明する手順を使用できます。これは次の場合に適しています:

- デプロイ予定のコンテント・ノード全体のメモリーに収まらないベクトル・データセットに対して、ベクトル検索用のインデックスを構築したい場合(ランキング/ブルート・フォース NN のためにベクトルを保存するだけではない場合)。
- 対象のベクトル・データがほぼ一度きりの書き込みであり(他のフィールドへの頻繁な書き込みは問題ありません)、コンテント・クラスターの再スケーリングが不要な場合。

## 手順

<Steps>
<Step>
インデックスするベクトル・フィールドを [paged](/ja/content/attributes/#paged-attributes) として宣言します。

```js
    schema docs {
        document docs {
            field myVectors type tensor<bfloat16>(chunk{}, x[384]) {
                indexing: attribute | index
                attribute: paged
            }
        }
    }
```

</Step>
<Step>
メモリーに収まるデータ量を計算します:

	属性の生データ・サイズを計算し(他の属性フィールドが多数ある場合を除き、ベクトルのみを対象とすれば十分近い値になります)、<br/>
	必要な [searchable-copies](/ja/reference/applications/services/content#searchable-copies) の数を掛け、<br/> 
	ベクトルに対するインデックスの分の余裕を持たせるために 1.2 を掛け、<br/>  
	ワーキング・メモリーの余裕を残すために 0.65 で割り、<br/>
	ドキュメントの総数を掛けます。<br/><br/>
	これにより、コンテント・クラスター内のすべてのノード(複数のグループがある場合は 1 グループ)にわたって必要な総メモリー量が得られます。<br/><br/>
	**例**: 上記の型で、10 億ドキュメント、1 ドキュメントあたり平均 10 チャンクの場合:<br/>
	10 \* 384\*2 bytes \* 2 \* 1.2 / 0.65 \* 1B = クラスター全体で合計 14.178 Gb のメモリー。
</Step>
<Step>
上記の計算でメモリーに収まるデータ・サブセットごとに、1 つのドキュメント・タイプを作成します。

**例:** `docs` タイプの 4 年分のドキュメントに対してベクトル・インデックスを作成したいが、クラスター全体でベクトル・データの 25% だけが収まるメモリーしか割り当てたくないとします。`docs` のサブタイプを年ごとに 4 つ、docs2021、docs2022、docs2023、docs 2024 として、4 つの異なるスキーマ・ファイルに作成します。これらはそれぞれ親タイプを継承し、それ以外は空でかまいません:

```js
  schema docs2021 inherits docs {
        document docs2021 inherits docs {
        }
    }
```

もちろん、ここに期間固有のフィールドやランキングを追加することもできます。
</Step>
<Step>
services.xml で、すべてのサブタイプを目的のコンテント・クラスターに追加します:

```js
 <content id="myClusterId" version="1.0">
        <documents>
            <document type="docs2021" mode="index" />
            <document type="docs2022" mode="index" />
            ...
        </documents>
```
</Step>
<Step>
各タイプを 1 つずつ完全にフィードします。その間、同時にクエリーは実行しないでください。
</Step>
<Step>
すべてのタイプの書き込みが完了したら、クエリー・トラフィックを適用できます。Vespa はデフォルトですべてのタイプを横断して検索しますが、[restrict](/ja/reference/api/query#model.restrict) クエリー・パラメーターを使用してサブセットに制限することも可能です。
</Step>
</Steps>
